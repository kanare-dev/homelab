# プロファイル（Omada のパラメーターシート）

画面の場所は、サイト > 構成 > ネットワーク設定 > プロファイル（グループ）と、デバイス設定 > ポートプロファイルである。実機の値は [`snapshot/profiles.json`](snapshot/profiles.json) にある。表の読み方は [README](README.md#表の読み方) にある。

| 画面 | 使っているか |
| --- | --- |
| グループ | 使う。ゲートウェイ ACL の送信元・宛先に使う（[下の節](#グループ)） |
| ポートプロファイル | 使う。スイッチのポートの VLAN を決める（[下の節](#ポートプロファイル)） |
| 時間範囲、レート制限、PPSK、RADIUS、LDAP、APN、証明書 | 使わない（書き出していない。使う機能が無い） |

## グループ

ゲートウェイ ACL（[セキュリティ](security.md#ゲートウェイ-acl)）から参照するグループである。ルールより先に作る（ルールの作成画面の「＋作成」からも作れる）。名前は `grp-<内容>` にする（[ACL の名前と説明の付け方](../acl.md)）。

IP-Port グループは、サブネット（CIDR）の一覧と、ポートの一覧を別々に持ち、ポートはグループの全サブネットにかかる。範囲（`10.77.10.2-10.77.10.9`）は書けない。そのため、ホストごとにポートが違うものは、グループを分けた（2026-11-27。許可の範囲は、分ける前の設計と同じ）。

| 名前 | 種類（`type`） | サブネット（`ipList`） | ポート（`portList`） |
| --- | --- | --- | --- |
| `grp-vm-infra` | IP グループ（0） | `10.77.20.10/32` | — |
| `grp-vm-monitoring` | IP グループ（0） | `10.77.20.11/32` | — |
| `grp-mgmt-omada-ui` | IP-Port グループ（1） | `10.77.10.3/32` | 8043 |
| `grp-mgmt-pve-ui` | IP-Port グループ（1） | `10.77.10.10/32` | 8006 |
| `grp-mgmt-metrics` | IP-Port グループ（1） | `10.77.10.3/32`、`10.77.10.10/32` | 9100 |
| `grp-mgmt-pve-admin` | IP-Port グループ（1） | `10.77.10.10/32` | 8006、22 |
| `grp-mgmt-omada-ssh` | IP-Port グループ（1） | `10.77.10.3/32` | 22 |
| `grp-mgmt-devices-web` | IP-Port グループ（1） | `10.77.10.0/29`、`10.77.10.8/31` | 80、443 |
| `grp-lab-access` | IP-Port グループ（1） | `10.77.40.0/24` | 22、80、443 |
| `grp-lab-mosh` | IP-Port グループ（1） | `10.77.40.0/24` | 60000-61000 |
| `grp-lab-metrics` | IP-Port グループ（1） | `10.77.40.0/24` | 9100 |
| `grp-dns` | IP-Port グループ（1） | `10.77.20.10/32` | 53 |

- `grp-mgmt-devices-web` の `/29` と `/31` は、機器の帯 `.2`〜`.9` を含む。`/29` には、ゲートウェイの `.1` と `vm-omada` の `.3` も入るが、`.1` は ACL の対象外で、`vm-omada` は 80/443 で待ち受けていないので、実害はない（[ACL の名前と説明の付け方](../acl.md)）。
- このほかに、組み込みのグループ `IPGroup_Any`（`0.0.0.0/0`）、`IPv6Group_Any`、`DomainGroup_Any` がある。使っていない。

## ポートプロファイル

スイッチのポートに割り当てる、VLAN などの設定の組である。ポートごとの割り当ては、[SG2210P（sw01）](device-sw01.md#ポート)にある。値は v2 の API（`lan-profiles`）で読んだ。

| 名前 | 種類（`flag`） | ネイティブ（`nativeNetworkId`） | タグ（`networkTagsSetting`） | VLAN の設定（`vlanConfigEnable`） | 使っているポート |
| --- | --- | --- | --- | --- | --- |
| `All` | 標準（0） | Management(Default) | すべて許可（0） | `false` | p1、p2、p5〜p10（VLAN は、ポート側の「VLAN設定」で決める。[SG2210P](device-sw01.md#ポート)） |
| `Disable` | 標準（0） | なし | すべてブロック（1） | `false` | なし |
| `Management` | 標準（0） | Management(Default) | すべてブロック（1） | `false` | なし（既定のネットワークに付く標準のプロファイル。下の注） |
| `access-trusted` | 自作（2） | Trusted | すべてブロック（1） | `true` | p3（Buffalo）、p4（ディスプレイ） |

- 4 つとも、PoE は「変えない」（`poe` が `2`）、スパニングツリーは有効（`Disable` を除く）、ポートの分離は無効、LLDP-MED は有効、802.1X は自動（`dot1x` が `2`）である。
- `access-trusted` は、2026-11-11 に作った。ネイティブを Trusted(30) にし、タグ付きのネットワークは通さない（access ポート）。ポート側の「VLAN設定」を「プロファイルに従う」にしないと、プロファイルを選んでもネイティブが変わらない（2026-11-17 に確認）。
- `Management` は、既定のネットワークに付いて Omada が自動で作る標準のプロファイル（`flag` が `0`）である。ネイティブが既定のネットワークで、タグ付きのネットワークを通さない。既定のネットワークは、もとは `Default`（VLAN1）だったが、2026-11-20 に Management（VLAN10）に統合し、名前を `Management(Default)` にした（[ADR-0032](../../../../adr/0032-merge-default-network-into-management-vlan10.md)、[手順書 25](../../../../operations/runbooks/25-merge-default-network-into-vlan10.md)）。プロファイルの名前も、これに合わせて `Default` から `Management` に変わったと見込む（変わった時点は確かめていない）。標準のプロファイルなので、消したり名前を変えたりせず、このままにする。どのポートにも割り当てていない。
- 2026-11-28 までの文書は、標準のプロファイルを「Disable・All・Default」と書いていた（統合の前の名前のまま。2026-11-28 に直した）。
