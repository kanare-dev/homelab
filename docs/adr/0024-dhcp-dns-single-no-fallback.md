# 0024. DHCP が配る DNS は `vm-infra` だけにし、フォールバックを配らない

- ステータス: 採用（段階 1 で ER605 に適用）。VLAN 化のあとの DNS のアドレスは、[0025](0025-address-octets-by-role.md) で `10.77.20.11` から `10.77.20.10` に変わった。判断は有効（Management の緊急用プールだけは、[0027](0027-servers-octet-bands-and-emergency-dns.md) でルーターの DNS を配る例外にした）
- 日付: 2026-11-03

## 背景

Buffalo は、DHCP で DNS を 2 つ配っている。`192.168.11.11`（AdGuard、`vm-infra`）と `1.1.1.1`（Cloudflare）。ER605 に交換するとき、この 2 つ目を引き継ぐかを決める必要があった。

- `vm-infra`（DNS・Caddy・Tailscale）は 1 台で、止まると家の名前解決が止まる（[INC-2026-10-22](../operations/incidents/README.md)）。
- 運用者は、仕事用の Windows PC を家のネットワークで使う。会社の方針で、PC の DNS の設定を変えられない。会社の VPN の接続先がホスト名なら、VPN に繋ぎ直すときに、家の DNS が要る（接続先の種類は未確認）。
- [VLAN 設計](../architecture/08-vlan-design.md)は、全 VLAN で `10.77.20.11` だけを配る方針だった。

## 決定

ER605 の DHCP が配る DNS は、`vm-infra`（段階 1 は `192.168.11.11`、VLAN 化のあとは `10.77.20.11`）**だけ**にする。`1.1.1.1` などのフォールバックは配らない。

- 仕事用 PC の DNS の設定は変えない。
- `vm-infra` が止まって、仕事に困るときは、仕事用 PC を、壁の WAN から出ている Wi-Fi（建物の共用ルーターの Wi-Fi）に、直接繋ぐ（[障害時切り分け](../operations/runbooks/11-troubleshooting.md#vm-infra-の停止で名前解決が止まったとき仕事用-pc)）。
- 実際に止まって困る頻度が高くなったら、再検討する。

## 理由

- フォールバックを配ると、端末が、2 つ目も使う。AdGuard の広告ブロックを通らない通信が出る。`lab.kanare.dev` の内部の名前（CoreDNS が持つ）が、2 つ目では引けず、たまに失敗する。原因の分かりにくい症状になる。
- 問い合わせの内容が、外部の DNS にも見える。
- 止まる頻度は、更新や再起動の時間を勤務時間の外にする運用で、小さくできる。止まったときの備えは、手動の切り替え（壁の Wi-Fi）で足りる。

## 代替案

| 案 | 内容 | 判断 |
| --- | --- | --- |
| A. 2 つ目に `1.1.1.1` | Buffalo と同じ | 見送り。理由の欠点が残る |
| B. 2 つ目にルーター（ER605）自身 | ER605 の DNS プロキシが、上流へ転送する | 見送り。内部の名前が引けない。A と同じ欠点 |
| C. 2 つ目に、別の AdGuard | 別の VM に、もう 1 つ立てる | 見送り。運用が増える。ホストが止まると、同じホストの VM は効かない |
| D. 1 つだけ（採用） | `vm-infra` だけ | 採用 |
| 仕事用 PC の DNS を手動で 2 つにする | 端末側のフォールバック | 見送り。会社の方針で、設定を変えられない |

## 影響と再検討の条件

- **受け入れるリスク**: `vm-infra` が止まると、家の名前解決が止まる。仕事用 PC は、壁の Wi-Fi に切り替えるまで、VPN に繋ぎ直せない場合がある。
- 段階 1（ルーターの入れ替え）で、DNS の配り方が変わる（Buffalo の `1.1.1.1` が無くなる）。不具合が出たら、まず DNS の変化を疑う。
- 次の場合は、新しい ADR で見直す。
  - `vm-infra` の停止で、仕事に困ることが、繰り返される。
  - 仕事用 PC の VPN の接続先が IP アドレスだと分かり、家の DNS が不要だと確認できた（この場合は、リスクが小さくなる）。
  - 別のホストを導入した（C を現実的にできる）。
