# 0032. 既定のネットワークを Management（VLAN10）に統合し、VLAN1 を使わない

- ステータス: 採用（実施済み。2026-11-20）
- 日付: 2026-11-19

## 背景

[ADR-0031](0031-stage3b-devices-before-controller.md) で、`vm-omada`（`10.77.10.3`）・SG2210P（`10.77.10.2`）・ER605 のコントローラーへの接続を、Management（VLAN10）に移した（2026-11-19）。残ったのは、次の 2 つ。

- ER605 が、コントローラーに名乗る住所は、**既定のネットワーク（VLAN1）の住所**（今は `192.168.11.1`）。コントローラーの画面の「IP アドレス」の欄にも、これが出る。`10.77.10.x` の管理系と、そろわない。
- 既定の LAN（`192.168.11.0/24`）は、Proxmox ホストが移れば、ER605 の住所以外、何も載らなくなる。

当初は、既定の LAN を `10.77.1.0/24` に付け替える案（案 A。VLAN1 は「使わない VLAN」として残す）だった。運用者は、「homelab なので、安定運用よりも、美しい構成を目指す」として、**既定のネットワーク自体を VLAN10 にして、VLAN1 をなくす案（案 B）**を希望した（2026-11-19）。

2026-11-19 に、確かめたこと:

- 公式の資料（[Omada Gateway の LAN ポートの VLAN 設定](https://support.omadanetworks.com/en/document/13070/)）に、「既定のネットワークの VLAN ID は変えられる」「必要なら、既定のネットワークを管理 VLAN として使うのがよい」とある。VLAN1 が必須、という記載は無い。
- 実機のコントローラー（6.3）の画面で、既定のネットワークの VLAN の番号を、**他の数字に変更できる**ことを確認した（変更はしていない）。
- 「LAN を追加」は、IP/マスクが必須で、ゲートウェイを持たない L2 だけのネットワークを作る選択肢は無い。ポートの native に選べるのは、既存のネットワークだけ。

## 決定

- **既定のネットワークを、VLAN10（Management）にする。** IP は `10.77.10.1/24`。今の別のネットワーク「Management」（VLAN10）は、**統合して、1 つにする**（消す）。VLAN1 は、使わない。緊急用の DHCP プール（`.240–.250`、リース 60 分、DNS `10.77.10.1`）は、そのまま引き継ぐ（[ADR-0025](0025-address-octets-by-role.md)）。
- **「どこにも繋がない VLAN」を、ダミーのネットワークとして作る。** 名前 `Blackhole`、VLAN 999、`10.77.99.1/24`、DHCP は無効、**ER605 のポートを 1 つも割り当てない**。ER605 に届かない VLAN なので、落ちた通信は、どこにも出られない。
- **ポートごとの native を、次のとおりにする**（untagged の通信が、意図しない面に入らないようにする）。

  | ポート | native |
  | --- | --- |
  | p2（Proxmox のトランク） | `Blackhole`（[ADR-0023](0023-proxmox-trunk-all-tagged.md) の「タグなしは、どこの VLAN にも入らない」を、VLAN1 に代えて、`Blackhole` で守る。タグ付きは、Management・Servers・Lab・IoT・DMZ ほか） |
  | p5・p6・p7（空き） | `Blackhole`（タグは全ブロック。いまは native VLAN1・タグ全許可で、開いている） |
  | p8（緊急用の入口） | Management（意図した入口。緊急用の DHCP プールがある。ER605 が止まっている間は DHCP も止まるので、Mac は静的アドレス）。2026-11-10 に p6 としたが、空きの PoE ポート（p5〜p8）を連続させるため、2026-11-19 に p8 に変えた |
  | p1（ER605 との接続） | Management（untagged VLAN10。ER605 側も、同じ VLAN10 の untagged） |
  | p3・p4（アクセス） | 変えない（Trusted、VLAN30） |

- **切り替えは、ER605 を先に「削除」（初期化）して、停止している間に、コントローラーの設定を直し、ER605 を再採用する。** ER605 は、導入のときの住所を覚える（ADR-0031 の実績）ので、VLAN10 側だけで導入する。Management を先に消すと、ER605 がコントローラーへの経路を失って、変更を受け取れなくなる、という問題を、この順序で避ける。手順は、[手順書 25](../operations/runbooks/25-merge-default-network-into-vlan10.md)。
- 先に、Proxmox ホストを `vmbr0.10`（`10.77.10.10`）に移す（[手順書 24](../operations/runbooks/24-pve-move-to-vmbr0-10.md)）。ホストが、p2 のタグなし（VLAN1）に居る間は、native を `Blackhole` にできない。

## 理由

- 管理系（ER605、SG2210P、`vm-omada`、Proxmox）が、すべて `10.77.10.x` にそろう。コントローラーの画面の ER605 の住所も、`10.77.10.1` になる。
- 「使わない VLAN1」が無くなる。VLAN1 は、工場出荷時の機器や、設定を間違えたポートの、既定の面になりやすい。案 B は、native を `Blackhole` にして、**意図した場所（p8）だけを Management にする**ので、いまの「空きポートが VLAN1 で開いている」状態より、むしろ締まる。
- 公式の資料が、既定のネットワークを管理 VLAN として使うことを、勧めている。

## 代替案

| 案 | 長所 | 短所 |
| --- | --- | --- |
| 案 B: 既定のネットワークを VLAN10 に統合（採用） | 管理系が `10.77.10.x` にそろう。VLAN1 がなくなる | ER605 の全面停止が、もう一度（約 30〜40 分）。native の設計（`Blackhole`）が要る |
| 案 A: 既定の LAN を `10.77.1.0/24` に付け替える | 切り替えが軽い（VLAN10 に触れない）。ADR-0023 の設計が、そのまま | ER605 の住所が `10.77.1.1` で、管理系とそろわない。VLAN1 が残る |
| 既定の LAN（`192.168.11.0/24`）のまま残す | 何もしない | 旧 LAN の住所体系が残る。ER605 の住所が `192.168.11.1` のまま |

## 影響と再検討の条件

- ADR-0023 は、置き換えない。**「タグなしの通信は、どこの VLAN にも入らない」という決定は、そのまま有効**で、p2 の native が、VLAN1 から `Blackhole` に変わるだけ（ADR-0023 に、その旨を追記した）。
- ADR-0028 の「今の LAN（VLAN1）」は、この ADR の実施のあと、なくなる。
- 実施の前に、画面で確かめること（未確認）: (1) SG2210P の管理インターフェースが、「Management」ネットワークに紐づいているか。Management を消したとき、SG2210P の管理 VLAN が、宙に浮いて、コントローラーから切れないか（切れたときは、SG2210P を再採用する。同じ VLAN10 の L2 なので、可能）。(2) Default の VLAN を 10 にしたとき、SG2210P の p1・p2 の untagged と tagged が、期待どおりに変わるか。(3) `Blackhole` を ER605 のポート 0 個で、作れるか（ポートの選択を、空にできるか）。
- 実施の結果が期待と違うときは、案 A に戻すかを、新しい ADR で決める。

## 実施の結果（2026-11-20）

期待どおりに完了した（ER605 の全面停止は、約 1 時間。予定は 30〜40 分で、超えた）。ER605 の既定のネットワークは `Management(Default)`（VLAN10、`10.77.10.1/24`）。VLAN1 は、なくなった。p2 と空きポート（p5〜p7）の native は `Blackhole`、p8（緊急用の入口）と p1 は native Management。

上の「未確認」の答え:

1. **`Management` は、そのままでは消せない。** スイッチの管理 VLAN と、スイッチのネイティブネットワーク（p8）に紐づいていて、先に外す。消した時点で、**スイッチから VLAN10 が消え、コントローラーから切れた**（想定どおり）。SG2210P の本体の画面（ER605 の DHCP から受けた住所）で、VLAN10 を足して、復旧した。
2. Default の VLAN を 10 にすると、p1・p8 の native は VLAN10 になった。ただし p2 は、コントローラーのタグ付きに Management を含めていなかったため、VLAN10 が untagged になった。**p2 のタグ付きに Management を含める**ことで直した。
3. ER605 は、スタンドアロンで、LAN を `10.77.10.1/24`（VLAN は 1 のまま。スイッチ p1 の PVID が 10）にして、Inform URL `10.77.10.3` で採用できた。
