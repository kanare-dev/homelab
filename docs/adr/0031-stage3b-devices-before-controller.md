# 0031. 段階 3b は、機器を先に VLAN10 へ移し、そのあとコントローラーを移す

- ステータス: 採用（未適用）
- 日付: 2026-11-19

## 背景

[ADR-0028](0028-defer-management-vlan10.md) で、管理系（Proxmox ホスト、`vm-omada`、ER605・SG2210P）の VLAN10 化を、段階 3b に分けた。段階 3b の前提は、「`vm-omada` の住所が変わったとき、採用済みの機器（ER605・SG2210P）が付いてくること」だった。

2026-11-18 に、実機で 2 回確かめた（[ロードマップ 13](../operations/roadmap/13-defer-management-vlan.md)）。

- `vm-omada` に VLAN10 の NIC（`10.77.10.3`）を足し、「デバイス管理アクセス」で新しい住所を機器に伝えた。新しい住所は伝わった（機器が `10.77.10.3` に接続を試した）が、接続は完了しなかった。
- 原因の一つは、非対称ルーティング（機器が旧 LAN から VLAN10 のアドレスに来た接続の返事が、`vm-omada` の旧 LAN 側の NIC から出る）だった。直しても、機器は付いてこなかった。

つまり、**機器が旧 LAN にいる間に、コントローラーの住所だけを動かす方式は、成功しなかった。**

## 決定

- **機器を先に VLAN10 へ移し、そのあとコントローラーを移す。** 順序は、次のとおり。
  1. SG2210P の管理 VLAN と IP を、VLAN10（`10.77.10.2`）にする。コントローラーは、旧住所（`192.168.11.12`）のまま。
  2. 「デバイス管理アクセス」を `10.77.10.3` にして、SG2210P が付いてくるか確かめる（機器とコントローラーが、同じネットワークにいる）。
  3. ER605 が付いてくるか確かめる。
  4. 付いてきたら、`vm-omada` を VLAN10 の 1 枚の NIC にする。
- **各手順に確認と止める条件を置く。** 手順 2 で付いてこなければ、そこで止める（機器のリセットと再採用に進む）。ER605 だけ付いてこなければ、ER605 だけ再採用する。
- 手順は、[段階 3b の作業](../operations/runbooks/23-network-stage-3b-management-vlan10.md)に書く。Proxmox ホストの移動（`vmbr0.10`）は、別の作業とする。

## 理由

- 機器とコントローラーが、同じネットワーク（`10.77.10.0/24`）にいれば、返事の経路の食い違いが起きない。最終形（`vm-omada` が VLAN10 の 1 枚）とも同じ形になる。
- 失敗しても、手順ごとに戻せる。SG2210P を動かしても、データの通信（ポートの VLAN）は変わらない見込み。
- 再採用（リセットと設定の復元）は、段階 1・2 で一度行った作業で、バックアップがある。この方式が通らなくても、行き止まりにならない。

## 代替案

| 案 | 長所 | 短所 |
| --- | --- | --- |
| 機器を先に動かす（採用） | 経路の問題が起きない。最終形と同じ形 | 手順が多い。「デバイス管理アクセス」が効くかは、手順 2 まで分からない |
| 機器が旧 LAN のまま、コントローラーだけ動かす | 手順が少ない | 2 回の試験で成功しなかった |
| 採用済みの機器に、住所を直接書き換える | 再採用が要らない | 手段が見つかっていない（採用済みの機器の画面には入れない） |
| 機器をリセットして、新しい住所で採用し直す | 確実 | 停止が長い（ER605 はインターネットが止まる） |

## 影響と再検討の条件

- 未確認のことが残る: SG2210P の管理 VLAN を変える画面の場所と、そのときに切れないか。ER605 が、旧 LAN の自分の住所を送信元にする影響。「デバイス管理アクセス」が効くか。結果は、手順書とロードマップ 13 に記録する。
- 手順 2 で SG2210P が付いてこなければ、「デバイス管理アクセス」は効かないと確定する。再採用を前提にした新しい ADR で、この判断を置き換える。
- **実施の結果（2026-11-19）**: 手順 1・2 は成功した（SG2210P は `10.77.10.3` に付いてきた）。手順 3 の ER605 は、旧 LAN で導入されたまま、付いてこなかった（1 回目の再採用で、旧 LAN で発見・導入させても、同じだった）。**ER605 を初期化して、VLAN10 側だけで再採用する（2 回目）と、ER605 が `10.77.10.3` を覚え、手順 4（`vm-omada` を NIC 1 枚にする）まで完了した。** 決定の方向（機器を先に動かす）は正しかった。ER605 は、導入のときの住所を覚える、という知見は、[手順書 23](../operations/runbooks/23-network-stage-3b-management-vlan10.md) の補正に書いた。残りは、Proxmox ホストの移動と、既定の LAN の付け替え。
- ADR-0028 は置き換えない。段階 3 の範囲の決定は、そのまま有効。
