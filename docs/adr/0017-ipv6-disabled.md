# 0017. IPv6 は無効にし、IPv4 だけで設計する

- ステータス: 採用（VLAN は未適用）
- 日付: 2026-11-01

## 背景

VLAN の設計（[VLAN 設計](../architecture/08-vlan-design.md)）は、IPv4 の `10.77.<VLAN>.0/24`（[ADR 0015](0015-vlan-address-scheme-10-77.md)）で、通信ポリシーをデフォルト拒否の許可表として組んでいる。上流（建物の共用ルーター、引っ越し先）が IPv6 を配ると、`10.77` の体系の外を通る経路ができる。IPv4 のルールだけでは、DMZ や Guests の隔離に穴があくことがある。現在の上流が IPv6 を配っているかは、決定時には確認していなかった（確認結果は「影響と再検討の条件」に追記）。

## 決定

IPv6 は無効にする。ER605 で IPv6 を有効にせず、各 VLAN にも IPv6 を配らない。通信ポリシーは IPv4 だけで完結させる。

## 理由

- 隔離する対象（DMZ、Guests、IoT）に、IPv6 という別の経路を作らずに済む。
- IPv6 用のファイアウォールルールを別に書いて、保守する負担を避けられる。
- 外出先からのアクセスは Tailscale で成り立っているので、IPv6 は必要ない。

## 代替案

- ULA や DHCPv6-PD を使って、IPv6 も各 VLAN に配る案は、学習にはなる。しかし、許可表を IPv6 用にも書く必要があり、設計が大きくなる。
- 上流を確認してから決める案は、IPv6 を無効にしても困る場面が今のところないので、選ばなかった。

## 影響と再検討の条件

- 段階 3 の疎通確認で、ER605 と各 VLAN に、IPv6 が配られていないことを確認する。
- 上流が IPv6 を配る場合も、LAN 側には出さない。
- IPv6 を使うことにしたときは、別に設計して新しい ADR を追加し、この ADR を置き換える。
- **現在の上流の確認結果**（2026-11-02、追記）: Mac にグローバル IPv6 アドレスが付いておらず、`curl -6` の接続先も、IPv4 を IPv6 の形に包んだ表記（IPv4-mapped）だった。このことから、現在の建物の上流は、IPv6 を配っていないとみてよい。この判断は変えない。ただし、確認したのは、Mac 1 台の、1 つのインターフェースだけである。
- 引っ越し先では、契約する前に、事業者や管理会社に、IPv6 に対応しているかと、各戸にどう配られるかを聞く。入居した後にも、同じ確認をする。
