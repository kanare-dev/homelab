# 0030. 段階 3 は戻す時刻を決めず、完了するまで作業する

- ステータス: 採用（未適用）
- 日付: 2026-11-10

## 背景

段階 3 の当日の手順は、「ここまでに疎通が取れなければ戻す」時刻を、作業の前に決める計画だった（[ADR-0004](0004-vlan-cutover-all-at-once.md) の「戻し手順が用意されていること」）。

ただ、段階 3 で戻す作業（SG2210P のポートと ER605 の VLAN を戻し、旧アドレスのコードで `terraform apply` する）も、それなりに時間がかかる。そのあと、改めて段階 3 をやり直すことになる。

[ADR-0028](0028-defer-management-vlan10.md) で、段階 3 では管理系（Proxmox ホスト、`vm-omada`、ER605・SG2210P）を動かさないことにした。そのため、段階 3 の作業中でも、コントローラーと Proxmox には、今の LAN から入れる。[ADR-0029](0029-stage3-acl-allow-all-then-tighten.md) で、当日の ACL は全許可にした。

## 決定

- **段階 3 の当日は、戻す時刻を決めない。** 戻す時間があるなら、その時間で作業を進め、完了させる。
- 作業中にインターネットが要るとき（調べもの、ファームウェアの取得など）は、端末を建物（壁）の Wi-Fi に繋ぐ。
- 戻し方（移行計画の 3-E、Runbook の「戻し方」）は消さない。機器の故障など、その日のうちに完了できない事情が出たときのために残す。

## 理由

- 運用者は一人暮らしで、止まって困る人がいない。ラボは止まっても人命や収入に関わらない（ADR-0004 と同じ）。
- 作業中の連絡や調べものは、建物の Wi-Fi で賄える。自宅の LAN が止まっていても、作業者が外と繋がれる。
- 管理系を動かさないので、作業中にコントローラーや Proxmox に入れなくなるおそれが小さくなる。途中で直しながら進められる。ただし、ゼロにはならない。手順 2 で SG2210P のポート（p1、p3）を変えるので、[INC-2026-11-08](../operations/incidents/2026-11-08-sg2210p-native-vlan-overwrite.md) のような操作ミスの余地は残る（戻し方の、ER605 の LAN ポートへの直結は残してある）。
- 時刻で区切って戻すと、戻す作業と、やり直しの作業が増える。

## 代替案

| 案 | 長所 | 短所 |
| --- | --- | --- |
| 戻す時刻を決め、過ぎたら戻す（従来） | 止まる時間の上限が決まる | 戻す作業と、やり直しが増える |
| 戻す時刻を決めず、完了まで作業する（採用） | やり直しがない。途中で直しながら進められる | 止まる時間の上限がない |

## 影響と再検討の条件

- 自宅の LAN が止まる時間の上限がない（リスクを受け入れる）。仕事用 PC（Trusted）も、作業が終わるまで自宅の LAN を使えない。
- ADR-0004 の条件「戻し手順が用意されていること」は、手順を残すことで満たす。
- 他に使う人がいて長時間止められなくなったとき、または建物の Wi-Fi が使えなくなったときは、戻す時刻を決める方式に戻す（この ADR を置き換える）。
- 段階 3b（管理系の VLAN10 化）は、この ADR の対象外。管理系を動かすので、段階 3b の前に、改めて決める。
