# 0044. 「文書が先」の設定値は、実機の画面で項目と選択肢を確かめてから書く

- ステータス: 採用
- 日付: 2026-11-28

## 背景

GUI でしか変えられない設定（Omada）と、壊れると影響が大きい変更は、「文書が先」にしている。変更後の値をパラメーターシートに書いて PR をマージし、そのあと実機を変える（[ADR-0033](0033-docs-first-by-change-type-and-diagram-order.md)）。

この運用では、変更後の値を、実機を見る前に書くことになる。設計書や仕様書、AI の知識だけから書くと、実機の画面に無い項目や、選べない値を書いてしまうおそれがある。運用者は、パラメーターシートを、机上だけで書かないことにした（2026-11-28）。

## 決定

1. 「文書が先」の変更で、パラメーターシートに変更後の値を書くときは、**先に実機の画面を開き、その項目があること、その値を選べる（入力できる）ことを確かめる**。確かめる間は、設定を保存しない。保存、適用、削除のボタンは押さない。
2. 確かめるのは、運用者か、Claude（ブラウザで管理画面を開く。読み取りだけにする）である。Claude が確かめたときは、運用者が画面と突き合わせてから「確認済み」にする。
3. 画面で確かめた値は、パラメーターシートに「未適用」と書き、画面の場所（メニューのパス）と、画面の項目名を添える。画面で確かめていない値は、パラメーターシートに書かない。ロードマップか手順書に「検討中」「未確認」として書く。
4. PR をマージしてから、実機の設定を変える。変えたあとは、`make omada-export` で書き出し、画面と書き出しで値を確かめて、「未適用」を外す（[ADR-0041](0041-omada-settings-exported-by-open-api.md)）。予測が外れた点は、同じ文書に書く。

## 理由

- パラメーターシートは、Omada の設定値の正である（[ADR-0040](0040-config-source-of-truth-by-location.md)）。実機で設定できない値が載ると、正が成り立たない。
- 画面を開くだけなら、実機は変わらない。「文書が先」の、変える前に見直せるという利点は、そのまま残る。
- Open API の仕様書には、キーと選択肢が載っている。しかし、機器や版によっては、画面に出ない項目や、選べない値がある。画面で確かめるのが確実である。

## 代替案

| 案 | 採らなかった理由 |
| --- | --- |
| 今のまま、机上で書く | 実機で設定できない値が、レビューを通ってしまう |
| 実機を変えてから、パラメーターシートを書く（「同時」にする） | 変える前に見直す機会が無くなる。VLAN や ACL のように、壊れると影響が大きい変更で、[ADR-0033](0033-docs-first-by-change-type-and-diagram-order.md) の理由がそのまま当てはまる |
| 変更計画（手順書）だけを先に書き、パラメーターシートは実施のあとに書く | 変更後の値が、パラメーターシートと手順書の 2 か所に分かれる。項目が画面にあるかの確認は、どちらに書く場合でも要る |

## 結果

- `CLAUDE.md` の「運用ドキュメント」の節と、[Omada のパラメーターシート](../architecture/lld/network/omada/README.md#更新のしかた)の「更新のしかた」に反映した。
- Buffalo（`wsr-1800ax4p.md`）など、Omada 以外の画面だけで変える設定にも、同じ決まりを当てはめる。
- 画面を開けないとき（機器がまだ無い、採用していないなど）は、その項目を「未確認」のまま、ロードマップか手順書に書く。機器を採用したあとに確かめて、パラメーターシートに移す。

詳細: [ADR-0033](0033-docs-first-by-change-type-and-diagram-order.md)、[ADR-0041](0041-omada-settings-exported-by-open-api.md)
