# 0002. 外部監視を導入しない

- ステータス: 採用
- 日付: 2026-10-22

## 背景

監視 VM（`vm-monitoring`）は PVE と同じストレージ・ホスト上にある。PVE ホスト、監視 VM、ストレージ全体が止まると、Alertmanager も止まり、Slack に通知が届かない。INC-2026-10-22 と同じ構造が残る。

## 決定

監視 VM・PVE ホストの停止を検知する外部監視は、現時点では導入しない。リスクは認識したうえで受け入れる。

## 理由

- 個人の homelab であり、停止の即時検知が必須ではない。
- 外部サービスのアカウント管理と、Webhook / ping URL の秘密情報管理が増える。
- 今回の障害（thin pool 枯渇）は、容量アラートで枯渇前に検知できる想定。ホストそのものの停止は、DNS 不達などの症状で気づける。

## 代替案

| 案 | 内容 |
| --- | --- |
| A. 外部 Heartbeat（Dead Man's Switch） | `Watchdog` を Healthchecks.io などへ定期送信し、途絶えたら外部から通知。**導入するなら第一候補** |
| B. 別ホストでの死活監視 | Raspberry Pi などが ping / HTTP で確認 |
| C. VPS でのリモート監視 | Tailscale 経由で死活確認 |
| D. 監視 VM を別ストレージへ分離 | ストレージ枯渇に巻き込まれない。ホスト停止は検知できない |
| E. 何もしない（現状） | 採用 |

各案の長所・短所は [監視・アラート](../services/monitoring.md#外部監視を導入しない判断2026-10-22)。

## 影響と再検討の条件

- PVE ホスト停止、監視 VM 停止、ストレージ全体障害は、気づくまで通知されない。
- 不在中に長時間気づけず困った、Home Assistant などの常時稼働が必要なサービスを載せた、または再び監視 VM を巻き込む障害が起きた場合に再検討する。
