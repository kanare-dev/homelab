# 0016. DMZ は VLAN60 に作り、まず Proxmox 上で公開せずに検証する

- ステータス: 採用（VLAN は未適用）。VLAN 番号は [0022](0022-vlan-set-and-ids.md) で VLAN70（`10.77.70.0/24`）に変わった。置き場所の判断は有効
- 日付: 2026-11-01

## 背景

ハニーポットや公開用の Web サーバーなど、外部に触れるものを置く場所として、DMZ の VLAN を足したい（[DMZ と外部公開](../operations/roadmap/07-dmz.md)）。Proxmox ホスト（ThinkCentre）の NIC は 1 つで、DMZ の VM は同じ VLAN-aware ブリッジに載る。VLAN 分離だけでは、ホスト自体が侵害されるリスクは消えない。また、管理画面（Omada、Proxmox）は現在、Tailscale と Caddy 経由で外出先から届く（[ADR 0005](0005-tailscale-only-remote-access.md)、[第5章 ネットワーク](../architecture/hld/05-network.md#管理画面への外部到達リスクを受け入れる)）。

## 決定

- DMZ を VLAN60（`10.77.60.0/24`、[ADR 0015](0015-vlan-address-scheme-10-77.md)）として、設計に加える。VLAN とファイアウォールルールは段階 3 で作り、DMZ に置くものは、07 の計画で追加する。
- DMZ の VM は、まず Proxmox の同じホストに置き、インターネットに公開しない範囲（07 の Phase 1〜3）で検証する。
- 将来は、別の小型 PC やラズパイなどを、DMZ 専用の機器にする。別の機器に移す時期（外部公開の前にするか）は、07 の Phase 1 で決める。
- 管理画面に外部から届く経路は、公開するものを置く前（07 の Phase 4 の前）に、Tailscale の ACL で整理する。

## 理由

- 機器を追加で買わなくても、DMZ の設計、ファイアウォール、ログの可視化を学べる。
- 公開しない範囲で使うなら、ホストが侵害されるリスクは、検証の範囲に収まる。
- 外部に触れるものを置くと、攻撃される面が増える。管理画面に届く経路を先に絞っておけば、侵害されたときに、被害が管理面まで広がりにくくなる。

## 代替案

- 最初から別の機器に置く案は、ホストが侵害されるリスクを避けられる。ただし、機器の購入と置き場所の確保が、先に必要になる。
- 同じホストのまま外部にも公開する案は、侵害されたときの被害が、Proxmox ホストと全 VM に及ぶ可能性がある。

## 影響と再検討の条件

- DMZ から内部への通信を遮断できるかどうかは、コントローラーモードの ACL で LAN → LAN を制限できるかに依存する（VLAN 設計の未決事項）。使えない場合は、代わりの方法を先に決める。
- 外部に公開する前に、別の機器に移すかどうかを再検討する。同じホストで公開する場合は、新しい ADR に、リスクを受け入れたことを記録する。
- 公開用の Web サーバーを Cloudflare Tunnel で公開するときは、ADR 0005 を置き換える新しい ADR を追加する。
