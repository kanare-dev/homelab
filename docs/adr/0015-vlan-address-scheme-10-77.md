# 0015. VLAN のアドレス体系を `10.77.<VLAN>.0/24` にする

- ステータス: 置き換え済み（→ [0022](0022-vlan-set-and-ids.md)）。アドレス体系 `10.77.<VLAN>.0/24` は有効で、VLAN の構成と ID だけが 0022 で変わった。「ホストの末尾オクテットは現在の値を引き継ぐ」は、[0025](0025-address-octets-by-role.md) で役割ベースに変わった
- 日付: 2026-11-01
- [ADR 0003](0003-vlan-address-scheme.md) を置き換える

## 背景

ADR 0003 は `10.<VLAN ID>.0.0/24`（例: Servers は `10.20.0.0/24`）と決めた。その後、DMZ の VLAN を足す計画（[DMZ と外部公開](../operations/roadmap/07-dmz.md)）が出た。また、この体系の第 2 オクテットは `10.10`〜`10.60` で、職場や他の VPN で使われやすい範囲（`10.10.x.x` など）に重なる。

## 決定

各 VLAN を `10.77.<VLAN ID>.0/24` にする（例: Servers は `10.77.20.0/24`）。

- 第 2 オクテット `77` は、この家に固有の値として固定する。家全体は `10.77.0.0/16` に収まる
- 第 3 オクテットを VLAN ID に揃える。ホストの末尾オクテットは、現在の値を引き継ぐ
- DMZ を VLAN60 として追加する（`10.77.60.0/24`）

## 理由

- 相手のネットワークが `10.77.0.0/16` を使っていない限り、被らない。`10.0`、`10.1`、`10.10`、`10.20`、`10.100` など広く使われる値を避けられる
- 家全体を `10.77.0.0/16` の 1 つの範囲で扱えるので、ファイアウォールや経路を書きやすい
- 第 3 オクテットが VLAN ID なので、アドレスを見ただけで VLAN が分かる
- どのみち全ホストのアドレスを変える移行なので、覚え直しの追加負担は小さい

## 代替案

- ADR 0003 のまま（`10.<VLAN>.0.0/24`）: 範囲が広く分散し、被りやすい値を含む。DMZ の追加でも VLAN ごとに範囲がばらける
- 他の値（`10.53` など）: 条件は同じ。選んだのは `10.77`

## 影響と残るリスク

- `10.77` が、外出先（職場・実家など）や引っ越し先の上流で使われていないか、確定前に確認する。上流が `10.77.x.x` を配っていると、WAN 側と被りうる
- VLAN 設計、通信ポリシー、Tailscale の広告範囲（`10.77.20.0/24`）、Terraform / Ansible / DNS / Caddy / Prometheus の IP を、段階 3 の付け替えで一緒に直す
- k3s の既定のアドレス（`10.42.0.0/16`、`10.43.0.0/16`）とは被らない
