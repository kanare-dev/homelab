# 0015. VLAN のアドレス体系を `10.77.<VLAN>.0/24` にする

- ステータス: 置き換え済み（→ [0022](0022-vlan-set-and-ids.md)）。アドレス体系 `10.77.<VLAN>.0/24` は有効で、VLAN の構成と ID だけが 0022 で変わった。「ホストの末尾オクテットは現在の値を引き継ぐ」は、[0025](0025-address-octets-by-role.md) で役割ベースに変わった
- 日付: 2026-11-01
- [ADR 0003](0003-vlan-address-scheme.md) を置き換える

## 背景

ADR 0003 は `10.<VLAN ID>.0.0/24`（例: Servers は `10.20.0.0/24`）と決めた。その後、DMZ の VLAN を足す計画（[DMZ と外部公開](../operations/roadmap/07-dmz.md)）が出た。また、この体系の第 2 オクテットは `10.10`〜`10.60` で、職場や他の VPN で使われやすい範囲（`10.10.x.x` など）に重なる。

## 決定

各 VLAN を `10.77.<VLAN ID>.0/24` にする（例: Servers は `10.77.20.0/24`）。

- 第 2 オクテットの `77` は、この家に固有の値として固定する。家全体のアドレスは、`10.77.0.0/16` に収まる。
- 第 3 オクテットは、VLAN ID に揃える。ホストの末尾オクテットは、現在の値を引き継ぐ。
- DMZ を VLAN60 として追加する（`10.77.60.0/24`）。

## 理由

- 相手のネットワークが `10.77.0.0/16` を使っていない限り、アドレスは重ならない。`10.0`、`10.1`、`10.10`、`10.20`、`10.100` のように、広く使われている値を避けられる。
- 家全体を `10.77.0.0/16` という 1 つの範囲で扱えるので、ファイアウォールのルールや経路を書きやすい。
- 第 3 オクテットが VLAN ID と同じなので、アドレスを見ただけで、どの VLAN かが分かる。
- どのみち全ホストのアドレスを変える移行なので、アドレスを覚え直す負担が増えることは、ほとんどない。

## 代替案

- ADR 0003 のまま（`10.<VLAN>.0.0/24`）にする案は、範囲が広く分散し、他のネットワークと重なりやすい値を含むので、選ばなかった。DMZ を追加しても、VLAN ごとに範囲がばらける。
- 他の値（`10.53` など）にする案もあるが、条件は `10.77` と同じである。そのため、`10.77` を選んだ。

## 影響と残るリスク

- `10.77` が、外出先（職場や実家など）や、引っ越し先の上流で使われていないかを、確定する前に確認する。上流が `10.77.x.x` を配っていると、WAN 側のアドレスと重なることがある。
- VLAN 設計、通信ポリシー、Tailscale の広告範囲（`10.77.20.0/24`）、Terraform、Ansible、DNS、Caddy、Prometheus に書いた IP は、段階 3 でアドレスを付け替えるときに、まとめて直す。
- k3s の既定のアドレス（`10.42.0.0/16` と `10.43.0.0/16`）とは重ならない。
