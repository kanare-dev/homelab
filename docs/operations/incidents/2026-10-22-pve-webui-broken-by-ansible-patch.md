## 要約

PVE の管理画面を開くとブラウザのコンソールに `Uncaught SyntaxError: Invalid or unexpected token` が出て、画面が描画されなかった。
原因は、サブスクリプション警告を消すために `ansible/roles/proxmox` が `proxmoxlib.js` へ当てているパッチだった。
置換文字列が `"void\\({//\\1"` と書かれていたため、`(` の前に**バックスラッシュが残り**、`void\({//Ext.Msg.show({` という不正な構文になっていた。
さらに正規表現がパッチ済みの文字列にも一致するため、**プレイブックを実行するたびに `void\({//` が 1 つずつ増えた**。

「バージョンのアップデートで起きる」という印象は、半分だけ合っていると考えている（推定）。アップデートがファイルを正規の状態に戻し、
その後にプレイブックを実行するたびに壊す、という繰り返しだった。**壊す側は常にプレイブックの実行**で、アップデートそのものではない（§3.2）。

調べると、ホストには `pve-nag-buster`（アップデートのたびに同じ警告を消す third-party のフック）も入っていて、
**同じファイルを 2 つの仕組みが書き換えていた**。

復旧は `apt-get install --reinstall proxmox-widget-toolkit` で数秒。恒久対応として、Ansible のタスクを
「判定式 `res.data.status.toLowerCase() !== 'active'` を `false` に置換する」だけの形に書き直した。
置換後は一致しないので冪等で、式を式に置き換えるだけなので構文を壊さない。

## 2. 調査結果

### 2.1 ブラウザのエラーの読み方

```text
Uncaught SyntaxError: Invalid or unexpected token            ← 根本。proxmoxlib.js がパースできない
pvemanagerlib.js: Cannot read properties of undefined (reading 'defaultText')   ← 派生
VM76:3 Uncaught TypeError: c is not a constructor            ← 派生
```

- 最初の `SyntaxError` だけが原因で、あとの 2 つは派生。`proxmoxlib.js`（`Proxmox.*` を定義する widget toolkit）が読み込めないため、
  `pvemanagerlib.js` が参照する `Proxmox.Utils` などが未定義になり、`defaultText` や `c is not a constructor` が起きる。
- `ext-all.js` の `500` は、Ext の動的ローダーが存在しないパスを取りに行った結果と推定する。復旧後に `/pwt/proxmoxlib.js` を直接取得しても `500` が返るため、**この 500 は原因ではない**（確定）。

### 2.2 壊れていた箇所（ホストの `proxmoxlib.js`、復旧前）

```js
if (
    res === null ||
    res === undefined ||
    !res ||
    res.false
) {
    void\({//void\({//void\({//void\({//Ext.Msg.show({
        title: gettext('No valid subscription'),
```

- `void\({//` が 4 個。バックスラッシュが原因で JavaScript として不正。
- 直前の `res.false` は `pve-nag-buster` の置換結果（`data.status.toLowerCase() !== 'active'` → `false`。同スクリプトは `proxmoxlib.js.orig` も作る）。**この時点で警告はすでに無効化されており、Ansible のパッチは不要だった**。
- パッケージの正規ファイルとの比較: `dpkg -V proxmox-widget-toolkit` が `proxmoxlib.js` を変更ありと報告。

### 2.3 繰り返し起きていた証拠

`/usr/share/javascript/proxmox-widget-toolkit/` に、Ansible の `backup: true` が作った `proxmoxlib.js.<pid>.<日時>~` が 19 個残っていた。

| 期間 | バックアップ数 | サイズの推移 |
| --- | --- | --- |
| 2026-03-11 19:19 | 1 | 版が古い（818189 バイト）。パッチの内容は未確認 |
| 2026-03-31 00:05〜00:57 | 11 | 820080 → 820179（毎回 +9） |
| 2026-03-31 17:09 | 1 | 820179 → 820188 |
| 2026-04-02 22:50〜22:57 | 2 | 820188 → 820206 |
| 2026-10-22 15:23〜16:35 | 4 | 820080 → 820116（毎回 +9） |

- 9 バイトは `void\({//` の長さに一致する。
- 4 月の 820206 バイトから 10 月の 820080 バイトに戻っているのは、2026-04-03 21:03 のアップデートがファイルを入れ替えたため。

### 2.4 同じファイルを書き換えていた仕組み

| 仕組み | いつ動くか | 方法 | 安全性 |
| --- | --- | --- | --- |
| `pve-nag-buster`（third-party） | `proxmox-widget-toolkit` / `pve-manager` の更新直後に自動実行（apt のフック） | 判定式を `false` に置換 | 安全 |
| Ansible `proxmox` ロール | プレイブックを実行するたび | `Ext.Msg.show({` の前に `void\({//` を挿入 | **不正な構文を作る。冪等でもない** |

## 3. 原因分析

### 3.1 直接原因（確定）

`ansible/roles/proxmox/tasks/main.yml` の次のタスク。

```yaml
- name: Remove no-subscription popup
  ansible.builtin.replace:
    path: /usr/share/javascript/proxmox-widget-toolkit/proxmoxlib.js
    regexp: "(Ext\\.Msg\\.show\\(\\{[^}]*title: gettext\\('No valid sub)"
    replace: "void\\({//\\1"
    backup: true
```

1. **エスケープの誤り**: `replace` はバックリファレンス（`\1`）を使うため、`(` の前の `\\` は `\` として出力に残る。意図は `void({//` だったが、実際には `void\({//` になった。ホストの実ファイルでこの文字列を確認した。
2. **冪等でない**: 正規表現が `Ext.Msg.show({ ... title: gettext('No valid sub` に一致する。パッチ済みの行にもコメントの内側でこの文字列が残っているので、**実行のたびに再び一致して先頭に追加される**。

### 3.2 「アップデートで起きる」という印象について（推定）

- 壊しているのは**プレイブックの実行**で、パッチを当て直すたびに壊れる。1 回目の実行で既に不正な構文になる（§2.3 の 10 月の例は 820080 → 820089 から）。
- パッケージのアップデートは、むしろ**ファイルを正規の状態に戻す**側（2026-04-03 の例）。壊れた状態は次のアップデートまで残る。
- 「アップデートのあとに壊れた」ように見える理由として、アップデート後に警告が再び出る → 気づいたユーザーがプレイブックを実行する、という流れが考えられる。今回の実行も、アップデートとは別の理由（INC-2026-10-22 の対応）だった。
- 過去の発生時に何を実行したかは記録が残っておらず、**未確認**。

### 3.3 要因の整理

| 要因 | 内容 | 区分 |
| --- | --- | --- |
| ① 置換文字列のエスケープ誤り | `void\({//` が不正な構文になる | 直接 |
| ② 冪等でない正規表現 | 実行のたびに増える。壊れたあとに再実行しても直らない | 直接 |
| ③ 書き換えの所有者が不在 | `pve-nag-buster` と Ansible が同じファイルを書き換え、互いを把握していない。`pve-nag-buster` が先に警告を消しているため、Ansible のパッチは実質不要だった | 構造 |
| ④ 書き込み後の検証がない | 構文チェックも、ブラウザでの確認もなく、壊れたまま完了扱いになる | 構造 |
| ⑤ ドキュメントがない | `pve-nag-buster` の存在や、このパッチの意図が `docs/` に書かれていなかった | 構造 |
| ⑥ `backup: true` の積み上がり | 実行のたびにバックアップが増え、19 個（約 15 MB）残っていた。復旧手段としては使われず、調査の手がかりにはなった | 副次 |

### 3.4 当初の仮説の評価

| 仮説 | 評価 |
| --- | --- |
| PVE のバージョンアップで JS が壊れる | **否定**。壊していたのは Ansible のパッチ。バージョンアップはむしろファイルを元に戻す |
| `pve-nag-buster` が壊している | **否定**。`res.false` への置換は構文として安全。壊れた箇所は `void\(` のみ |
| ブラウザのキャッシュ | 復旧後の再読み込みで念のため必要になる可能性はあるが、**原因ではない**（サーバー側のファイルが壊れていた） |

## 4. 対応

### 4.1 暫定対応（復旧）

```bash
# PVE ホストで実行
apt-get install --reinstall -y proxmox-widget-toolkit
```

- ファイルが正規の状態に戻り、`pve-nag-buster` のフックが警告を無効化して `pveproxy` を再起動する。
- 確認: ホストから取得した `proxmoxlib.js`・`ext-all.js` が `node --check` を通ること、`void\(` が 0 件であること。
- **想定外の副作用**: `--reinstall` のつもりが、リポジトリの最新版を入れた。`proxmox-widget-toolkit` は **5.1.8 → 5.2.10** に上がった（`pve-manager` は 9.1.7 のまま。`pve-manager` の依存条件は `>= 5.1.1` で満たす）。管理画面の表示に問題が出ていないかは §5 の #3 で確認する。
- 同じ状況での入れ直しは、バージョンを固定する（`apt-get install --reinstall proxmox-widget-toolkit=<現在の版>`）のが安全。

### 4.2 恒久対応（実装済み）

`ansible/roles/proxmox/tasks/main.yml` のタスクを次のように書き換えた。

```yaml
- name: Remove no-subscription popup
  ansible.builtin.replace:
    path: /usr/share/javascript/proxmox-widget-toolkit/proxmoxlib.js
    regexp: "res\\.data\\.status\\.toLowerCase\\(\\) !== 'active'"
    replace: "false"
  notify: restart pveproxy
```

| 性質 | 理由 |
| --- | --- |
| 構文を壊さない | 判定の**式**を `false` という**式**に置換するだけ。コメントアウトや括弧の挿入をしない |
| 冪等 | 置換後は `!== 'active'` が残らず、再び一致しない |
| 他の仕組みと衝突しない | `pve-nag-buster` と同じ判定式を対象にする。どちらが先に当てても、後からは一致しない |
| 失敗しても無害 | 将来のバージョンで式が変わると一致せず、何もしない。警告が出るだけ |
| 余計なファイルを作らない | `backup: true` を外した。戻すときは `apt-get install --reinstall` を使う |

検証:

- ローカルのテストファイルで 2 回実行し、1 回目は `changed`、2 回目は `ok`（変更なし）、結果のファイルは `node --check` を通ることを確認した。
- 実機で `ansible-playbook playbooks/proxmox.yml` を実行し、`changed=0` で終わること（`pve-nag-buster` が先に当てた状態でも壊れない）を確認した。
- 実機で警告を当て直す経路（正規の状態のファイルに対して新しいタスクが `changed` になること）は、**未確認**。`--reinstall` の直後に `pve-nag-buster` が先に当てたため。

### 4.3 見送った対策（判断の記録）

| 対策 | 判断 | 理由と再検討の条件 |
| --- | --- | --- |
| パッチ自体をやめる（警告を出したままにする） | 見送り | ログインのたびのダイアログは不便。ただし、パッチが再び問題を起こすなら、この選択に切り替える |
| `pve-nag-buster` を Ansible で管理する | 見送り | 同じ判定式を Ansible が当てるため、機能は重なっている。third-party の導入物を IaC に取り込むと管理対象が増える。どちらかが動かなくなったら再検討 |
| apt フックを自前で用意する | 見送り | `pve-nag-buster` が同じことをしている。重複させると、所有者が不明確になる今回の要因を再現する |
| 書き込み後に JS の構文チェックを Ansible に組み込む | 見送り | PVE ホストに Node.js がない。置換の対象を「式を式に置き換えるだけ」にしたため、構文を壊す経路自体がなくなった |
| ホストの保留中アップデートを適用する | 見送り | 当面は更新しない方針。更新は PVE 9.1 → 9.2 のマイナーバージョンアップで、QEMU のメジャー更新とカーネル更新（全 VM の停止を伴う再起動）を含み、バックアップもない。セキュリティ修正（61 件）が溜まる点は受容する。再検討の条件: 公開サービスを載せるとき、`vzdump` を導入したとき、管理画面や VM に不具合が出たとき |
| 管理画面の死活監視（`proxmoxlib.js` の取得と構文チェック） | 見送り | 管理画面の障害は VM とサービスに影響せず、ユーザーが即座に気づく。監視を増やすほどの価値がない |

## 6. ポストモーテム

### 6.1 影響

- PVE の管理画面が使えなかった。VM の稼働、DNS、監視、各サービスには影響なし。
- ホストへの SSH、`qm`、`pvesh` などの CLI は使えた。管理画面が使えない間も、VM の操作は CLI で可能だった。
- 影響の大きさは、管理画面を開く頻度で決まる。今回は INC-2026-10-22 の対応の最中で、画面が必要な場面だった。

### 6.2 根本原因（5 Whys）

1. **なぜ画面が開けなかったか** → `proxmoxlib.js` に不正な構文があり、ブラウザがパースに失敗したから。
2. **なぜ不正な構文があったか** → Ansible のタスクが `void\({//` を書き込んだから（`\` が残った）。
3. **なぜ増え続けて、直らなかったか** → 正規表現がパッチ済みの文字列にも一致し、実行のたびに追加されたから。
4. **なぜ気づかず完了したか** → 書き込み後に構文もブラウザでの表示も確認しない手順だったから。
5. **なぜそのタスクが存在したか** → `pve-nag-buster` ですでに警告を消す仕組みがあった（導入は 3/8）のに、それを把握せず、同じ目的の 2 つ目の仕組みを足したから。

### 6.3 うまくいったこと / いかなかったこと / 幸運だったこと

| 区分 | 内容 |
| --- | --- |
| うまくいった | ブラウザのエラーから、ホストのファイルを直接見ることで原因を特定できた。サイズの推移でバックアップファイルから過去の発生を裏づけられた |
| うまくいった | 管理画面の障害は VM に波及しない構成（管理プレーンとデータプレーンが分離）で、サービスは止まらなかった |
| いかなかった | `--reinstall` が最新版への更新を伴い、意図しないバージョン変更を起こした |
| いかなかった | `backup: true` のファイルを、過去の発生時に誰も気にしなかった。19 個の積み上がりが警告のサインだった |
| 幸運だった | 壊れていたのが管理画面だけで、`pveproxy` が起動していて SSH で調査と復旧ができた |

### 6.4 教訓

1. **システムのファイルを書き換えるなら、置換は式を式に置き換えるだけにする。** コメントアウトや括弧の挿入は構文を壊しやすい。
2. **置換の正規表現は、置換後の文字列に一致しないことを確認する。** 実行を 2 回繰り返して、2 回目が `changed` にならないことを確認するだけで、冪等性の問題は見つかる。
3. **同じファイルを書き換える仕組みを足す前に、既存の仕組みを調べる。** 今回は `pve-nag-buster` がすでに警告を消していた。
4. **「アップデートで壊れる」と思ったときは、アップデートそのものではなく、そのあとに実行したものを疑う。**
5. **`--reinstall` はバージョンを固定する。** 指定しないと最新版を入れる。

### 6.5 残っているリスク

| リスク | 評価 |
| --- | --- |
| 将来のバージョンで判定式が変わる | 一致せず、警告が出るだけ（無害）。管理画面は壊れない |
| `proxmox-widget-toolkit` 5.2.10 と `pve-manager` 9.1.7 の混在 | 依存条件は満たすが、両者の版がずれている。管理画面で不具合が出たら、§4.3 のアップデートの見送りを見直す |
| `pve-nag-buster` の保守が止まる | 本タスクが同じ置換をするので、`pve-nag-buster` が動かなくなっても、プレイブックの実行で当て直せる |
