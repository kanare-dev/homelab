# 既定のネットワークを Management（VLAN10）に統合する

**状態: 実施済み（2026-11-20）。** 当日の記録と、次にやるなら直す点は、末尾の「実施の記録（2026-11-20）」。 [ADR-0032](../../adr/0032-merge-default-network-into-management-vlan10.md) の実施の手順。既定のネットワーク（VLAN1、`10.77.1.0/24`。2026-11-19 の夜に、`192.168.11.0/24` から付け替えた）を、VLAN10（`10.77.10.1/24`）にして、別にある「Management」ネットワークと統合する。VLAN1 は使わなくなる。**ER605 の全面停止（約 30〜40 分）を伴う。** 今夜（2026-11-19）の ER605 の再採用（[ロードマップ 13](../roadmap/13-defer-management-vlan.md#er605-の再採用の手順と結果2026-11-19-に実施)）と同じ形の作業。

- **先に、[Proxmox ホストの移動](24-pve-move-to-vmbr0-10.md)を済ませる。** ホストが p2 のタグなし（VLAN1）に居る間は、p2 の native を `Blackhole` にできない。
- 秘密の値と、機器の MAC アドレスは書かない（台帳へ）。ER605 の管理者のパスワードは、再採用のたびに作り直す（台帳へ）。
- **未確認のことが多い。** 「未確認」と書いた点は、当日に画面で確かめる。手順を変えたら、この文書も直す。

## 考え方（なぜ、この順序か）

- Management を先に消すと、ER605 は、コントローラー（`10.77.10.3`）への経路（VLAN10 のインターフェース）を失い、既定のネットワークの変更を、受け取れなくなる。
- そこで、**ER605 を、先に、コントローラーで「削除」（初期化）する。** 停止している間に、コントローラーの設定を直し、ER605 を、新しい設定で再採用する。ER605 は、導入のときの住所を覚える（[ADR-0031](../../adr/0031-stage3b-devices-before-controller.md)）ので、**VLAN10 側だけで導入する**。
- 停止中も、SG2210P と `vm-omada` は、同じ VLAN10 の L2 なので、つながり続ける。Mac は、**p8（緊急用）を、Management の native にして**、そこからコントローラーに入る（ER605 が止まっていても、届く）。**ER605 が止まっている間は DHCP も止まるので、Mac には、`10.77.10.x`（例 `10.77.10.50`、GW なし）を静的に振る。** 緊急用の DHCP プール（`.240`〜`.250`）が効くのは、ER605 が生きていて、コントローラーだけが壊れたとき。

- [ ] **Omada のバックアップ**（設定とサイト）を取る（iCloud Drive、日付つき）。**SG2210P の各ポート（p1・p2・p5〜p8）の VLAN 設定（ネイティブとタグ）、ネットワーク一覧を、画面で控える**（戻すときに使う）。
- [ ] Mac に、有線の口が 2 つある（普段のディスプレイ経由と、USB の LAN アダプタ）。物理コンソール、モバイル回線のスマホ。作業の間は、全 VLAN が止まる。
- [ ] 作業時間を確保する（40〜60 分）。作業中に出るアラートは、想定内。

## 1. 事前の設定（ER605 に影響しない・止まらない）

1. **`Blackhole` ネットワークを作る**: 「設定 → ネットワーク設定 → LAN → 追加」。名前 `Blackhole`、VLAN 999、IP `10.77.99.1/24`、**DHCP サービスは「無効」**（初期値は「DHCP サーバー」。必ず切り替える）。「デバイスポートを選択」は、**「スキップ」で、ポートを 0 個にして進められる**（2026-11-19 に確認。保存はしていない）。
   - ただし、確認の画面に、**ER605 の LAN ポート（WAN/LAN2・3、LAN4・5）に、VLAN 999 が自動で入り、SG2210P の「全て許可」のトランクポート（p1・p2・p5〜p10）にも、VLAN 999 が自動で追加される**、と出る。つまり、ER605 に `10.77.99.1` のゲートウェイができる。そのままだと、p2 のタグなしの通信が ER605 まで届き、ブラックホールにならない。
   - 対策: **p1（ER605 との接続）のタグを「全て許可」から「カスタム」に変え、`Blackhole` を除いた VLAN だけを、タグ付きにする**。これで、VLAN 999 は、SG2210P の中だけに閉じる。ACL を絞るとき（目標 2026-12-01）に、`Blackhole` の送信元を、全拒否にする規則も足す（二重の守り）。
2. **ポートの VLAN を、ポートごとに直す**（2026-11-19 の確認: プロファイル `All`・`Default` は VLAN 設定が「オフ」で、p1・p2・p6 は、ポートごとの「カスタム」。プロファイルは作らず、ポートを直接直す。「設定 → デバイス設定 → スイッチ → ポートの設定」）:
   - p8（緊急用）: ネイティブ Management(10)。タグは「全て許可」のまま。（2026-11-19 に、p6 から p8 に変えた。空きの p5〜p7 が連続し、機器を p5 から前詰めで増やせる）
   - p2（Proxmox）: ネイティブ `Blackhole`。タグは、Management(10)・Servers(20)・Lab(40)・IoT(50)・DMZ(70) と、今のとおり（Trusted・Guests）の、カスタム。
   - p1: ネイティブ Management(10)（案 B の後の既定のネットワークと同じ）。タグはカスタム（上のとおり、`Blackhole` を除く）。
   - p5・p6・p7（空き）: ネイティブ `Blackhole`、タグ「全てブロック」。
   - p3・p4: 変えない（`access-trusted`。ネイティブ Trusted(30)、タグ「全てブロック」）。
3. **p8 を、Management の native にする**（緊急用の入口を、先に。Mac が、停止中に、コントローラーに入るため）。確認: p8 に Mac を繋ぎ、`10.77.10.x`（DHCP、またはこの時点では静的）を受け取り、`https://10.77.10.3:8043` に届く。**届くことを確認してから、先に進む。**
4. **p2 を `Blackhole` の native にする**（ホストと全 VM は、すでにタグ付きなので、影響しない見込み）。確認: Proxmox の Web UI（`10.77.10.10:8006`）、全 VM に届く。**届かなければ、すぐ戻す**（ネイティブを Default(1) に）。
5. **p5・p6・p7 を、`Blackhole` の native・タグ全ブロックにする**（空きポート。何も繋がっていない）。
6. **SG2210P の管理インターフェースの確認**（次の「未確認」の 1）。

## 3. コントローラーの設定を直す（停止中）

Mac を p6 に繋ぎ、`https://10.77.10.3:8043`（サイトのビュー `kanare-homelab`）に入る。

1. **「Management」ネットワークを消す。** SG2210P の管理インターフェースが「Management」に紐づいていて、消せない・SG2210P が切れる、場合がある（**未確認**）。そのとき:
   - SG2210P は、同じ VLAN10 の L2 なので、コントローラーから再採用できる（本体のリセットが要る。リセットの秒数は、[ER605 のときの報告](https://community.tp-link.com/en/home/forum/topic/598154)を参考に、確認する）。
   - 消せないときは、先に、SG2210P の管理 VLAN の設定を外す方法を、画面で探す。
2. **既定のネットワーク（Default）を編集する**: 名前 `Management`、VLAN `10`、IP/マスク `10.77.10.1/24`、DHCP サーバーは、**緊急用の範囲 `10.77.10.240`〜`.250`、リース 60 分、DNS `10.77.10.1`**。
3. **SG2210P の管理インターフェース**: 「デバイス → sg2210p → 設定 → インターフェース」で、`Management`（VLAN10、新しい既定のネットワーク）の管理 VLAN を有効にし、**静的 `10.77.10.2/24`、GW・DNS `10.77.10.1`**。旧 VLAN1 のインターフェース（`10.77.1.x`、DHCP）は、無効にする（もう無い）。

1. `http://192.168.0.1` → ウィザード（管理者アカウント。台帳へ）。WAN は DHCP。「Manually Connect to Omada Controller」に、Inform URL **`10.77.10.3`**。

## 事前確認の結果（2026-11-19。画面を見ただけで、何も変えていない）

- SG2210P の管理インターフェース（「デバイス → sg2210p → 設定 → インターフェース」）: `Default`（VLAN1）と `Management`（VLAN10）が有効で、**管理 VLAN の印は `Management` に付いている**。`Management` を消すと、管理インターフェースが宙に浮く。**手順 3 の 1 のとおり、消したあと、SG2210P が切れる前提で臨む**（再採用の準備をしておく）。
- `Blackhole` は、ER605 のポートを 0 個にして作れる。ただし、VLAN 999 は、ER605 のポートと、SG2210P のトランクに、自動で入る（手順 1 の対策を参照）。
- ポートの VLAN: p1・p2・p6 は、すべて、ネイティブ Default(1)・タグ「全て許可」。**案 B で既定のネットワークが VLAN10 になれば、これらのネイティブは、自動で VLAN10 になる見込み**（未確認）。p2 は、`Blackhole` に変えるまで、VLAN10 のタグなしの面になるので、**p2 の変更を、先に済ませる**。
- ポートプロファイルは、`Disable`・`All`・`Default`・`access-trusted` の 4 つ。`All`・`Default` の VLAN 設定は「オフ」。

## 実施の記録（2026-11-20）

結果: 完了。ER605 の全面停止は、約 1 時間（予定は 30〜40 分）。VLAN1 はなくなり、既定のネットワークは `Management(Default)`（VLAN10、`10.77.10.1/24`）。コントローラーの接続元 IP は、ER605 が `10.77.10.1`、SG2210P が `10.77.10.2`。

### 手順どおりに進んだところ

- 手順 1（`Blackhole` の作成、p1 のタグ、p8・p2・p5〜p7 の native）: 止まらずに済んだ。Mac は、緊急用の入口 p8 から、そのまま使えた。
- ER605 の「削除」→ 再採用: 初期化後の ER605 は、`192.168.0.1`（工場出荷）で起動し、LAN を `10.77.10.1/24`（VLAN は 1 のまま）、Inform URL を `10.77.10.3` にしたら、コントローラーに繋がった。**ER605 の LAN の VLAN を 10 にする必要はなかった**（スイッチ p1 の PVID が 10 で、untagged が VLAN10 になる）。UFW の `192.168.0.0/24` の許可や `ip route` も、要らなかった。
- 適用後、各 VLAN のゲートウェイは、約 4 分で戻った。

### 手順書とずれたところ（次にやるなら、こう直す）

1. **`Management` は、そのままでは消せない。** 「スイッチ管理 VLAN」と「スイッチのネイティブネットワーク（p8）」に紐づいている。先に、(a) スイッチの管理 VLAN を `Default`（VLAN1）に付け替え、(b) p8 のネイティブを Default(1) に変える。
2. **`Management` を消すと、スイッチから VLAN10 が消え、コントローラー（VLAN10）に届かなくなる**（SG2210P が切れる。想定どおり）。しかも、コントローラーは VLAN10 にしか居ないので、**Mac も届かなくなる**。復旧の手順:
   - 切れたスイッチは、ER605 の DHCP（工場出荷の `192.168.0.0/24`）から `192.168.0.100` を受け取る。Mac の `en7`（p8、untagged）に `192.168.0.50` を振ると、本体の画面（`https://192.168.0.100`）に入れる。ログインは、サイトのデバイスアカウント（台帳）。
   - 本体の「L2 FEATURES → VLAN → 802.1Q VLAN」に、VLAN10 を、**tagged ポート p1・p2・p8** で足す（保存は右上の「Save」も）。これで、Mac の VLAN10 のタグ付きインターフェースから、コントローラーに届く。
   - 本体の「L3 FEATURES → Interface」に、VLAN10 の静的 `10.77.10.2/255.255.255.0` を足す（Inform URL は、すでに `10.77.10.3`）。
   - **コントローラーで、`Default` を VLAN10 に変えると、配られた設定で、ポートの VLAN が変わる**（p1・p8 の native が VLAN10 になる）。このあと、Mac は、`en7` の untagged に `10.77.10.x` を付ける（タグ付きでは届かなくなる）。
3. **p2 のタグ付きに Management を含める。** コントローラーの p2（Port2）の設定が、タグ付きに Management を含めていなかった。そのため、VLAN10 が p2 の untagged になり、Proxmox・`vm-omada` に届かなくなった（本体の画面で気づいた）。手順 1 で p2 を直すとき、タグ付きは、Management・Servers・Trusted・Lab・IoT・Guests・DMZ の 7 つ（`Blackhole` と `Default` は外す）にする。
4. **Mac の VLAN10 のタグ付きインターフェース（作業用）は、MTU を 1496 に下げる。** USB LAN アダプタが、タグの 4 バイトの分を通せず、TLS（HTTPS）が止まった。`sudo networksetup -createVLAN Mgmt10 en7 10`、`sudo ifconfig vlan0 mtu 1496`、`sudo networksetup -setmanual "Mgmt10 Configuration" 10.77.10.50 255.255.255.0`。作業のあとは `deleteVLAN` で消す。
5. **ER605 は、既定でクラウド管理（Cloud-Based Controller Management）が有効で、Online になる。** ローカルのコントローラーだけで使うなら、無効にする。
6. **設定結果の「失敗」の通知（タイムアウト）は、スイッチが切れている間の古い記録だった。** 再接続のあと、「再度適用」は、押さない（コントローラーの設定のほうが、手当てした設定を上書きする）。先に、コントローラーの設定（p2 のタグ、管理インターフェースの静的 IP）を、手当てに合わせる。
7. 緊急用の入口 p8 の DHCP（`10.77.10.240`）は、ER605 の復旧後に、確認できた。
