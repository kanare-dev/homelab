# 既定のネットワークを Management（VLAN10）に統合する

**状態: 草案（未実施）。** [ADR-0032](../../adr/0032-merge-default-network-into-management-vlan10.md) の実施の手順。既定のネットワーク（VLAN1、`192.168.11.0/24`）を、VLAN10（`10.77.10.1/24`）にして、別にある「Management」ネットワークと統合する。VLAN1 は使わなくなる。**ER605 の全面停止（約 30〜40 分）を伴う。** 今夜（2026-11-19）の ER605 の再採用（[ロードマップ 13](../roadmap/13-defer-management-vlan.md#er605-の再採用の手順と結果2026-11-19-に実施)）と同じ形の作業。

- **先に、[Proxmox ホストの移動](24-pve-move-to-vmbr0-10.md)を済ませる。** ホストが p2 のタグなし（VLAN1）に居る間は、p2 の native を `Blackhole` にできない。
- 秘密の値と、機器の MAC アドレスは書かない（台帳へ）。ER605 の管理者のパスワードは、再採用のたびに作り直す（台帳へ）。
- **未確認のことが多い。** 「未確認」と書いた点は、当日に画面で確かめる。手順を変えたら、この文書も直す。

## 考え方（なぜ、この順序か）

- Management を先に消すと、ER605 は、コントローラー（`10.77.10.3`）への経路（VLAN10 のインターフェース）を失い、既定のネットワークの変更を、受け取れなくなる。
- そこで、**ER605 を、先に、コントローラーで「削除」（初期化）する。** 停止している間に、コントローラーの設定を直し、ER605 を、新しい設定で再採用する。ER605 は、導入のときの住所を覚える（[ADR-0031](../../adr/0031-stage3b-devices-before-controller.md)）ので、**VLAN10 側だけで導入する**。
- 停止中も、SG2210P と `vm-omada` は、同じ VLAN10 の L2 なので、つながり続ける。Mac は、**p6（緊急用）を、Management の native にして**、そこからコントローラーに入る（ER605 が止まっていても、届く）。

## 0. 準備（当日の前）

- [ ] Proxmox ホストが、`10.77.10.10`（`vmbr0.10`）に移っている（手順書 24）。VM が、すべてタグ付き（`vlan_id` が `null` の VM が無い）。
- [ ] **Omada のバックアップ**（設定とサイト）を取る（iCloud Drive、日付つき）。**ポートプロファイル、SG2210P の各ポートの設定、ネットワーク一覧を、画面で控える**（戻すときに使う）。
- [ ] Mac に、有線の口が 2 つある（普段のディスプレイ経由と、USB の LAN アダプタ）。物理コンソール、モバイル回線のスマホ。作業の間は、全 VLAN が止まる。
- [ ] 作業時間を確保する（40〜60 分）。作業中に出るアラートは、想定内。
- [ ] ER605 の設定値を控える（[ER605 の設定](../../hardware/er605/settings.md)と照合）: WAN は DHCP、各 VLAN のゲートウェイ・DHCP の範囲・リース・DNS。**Management の緊急用の DHCP プール（`.240–.250`、リース 60 分、DNS `10.77.10.1`）を、新しい既定のネットワークに引き継ぐ。**

## 1. 事前の設定（ER605 に影響しない・止まらない）

1. **`Blackhole` ネットワークを作る**: 「設定 → ネットワーク設定 → LAN → 追加」。名前 `Blackhole`、VLAN 999、IP `10.77.99.1/24`、DHCP は無効。**「デバイスポートを選択」で、ER605 のポートを 1 つも選ばない**（空にできるか、未確認）。
2. **ポートプロファイルを作る**（「設定 → デバイス設定 → スイッチ → ポートプロファイル → プロファイルを追加」）:
   - `trunk-pve`: ネイティブネットワーク `Blackhole`、タグ付きネットワーク: Management(10)・Servers(20)・Lab(40)・IoT(50)・DMZ(70)、そのほかの全部（Trusted・Guests は、今のとおり）。
   - `spare-blackhole`: ネイティブネットワーク `Blackhole`、ネットワークタグは**全ブロック**。
   - `emergency-mgmt`: ネイティブネットワーク Management(10)、タグ付きは今の `All` と同じ。
3. **p6 を `emergency-mgmt` にする**（緊急用の入口を、先に Management の native にする。Mac が、停止中に、コントローラーに入るため）。確認: p6 に Mac を繋ぎ、`10.77.10.x`（DHCP、またはこの時点では静的）を受け取り、`https://10.77.10.3:8043` に届く。**届くことを確認してから、先に進む。**
4. **p2 を `trunk-pve` にする**（Proxmox のトランク。ホストと全 VM は、すでにタグ付きなので、影響しない見込み）。確認: Proxmox の Web UI（`10.77.10.10:8006`）、全 VM に届く。**届かなければ、すぐ戻す**（元のプロファイルに）。
5. **p5・p7・p8 を `spare-blackhole` にする**（空きポート。何も繋がっていない）。

## 2. ER605 を「削除」する（ここから、全面停止）

1. コントローラーの「デバイス」（サイトのビュー）で、ER605 の「削除」→ 確認の「削除」（初期化される）。
2. `192.168.0.1` が応答する（約 2 分）まで待つ。Mac の USB アダプタを、**p6** に挿しておく（コントローラーの画面に入るため）。

## 3. コントローラーの設定を直す（停止中）

Mac を p6 に繋ぎ、`https://10.77.10.3:8043`（サイトのビュー `kanare-homelab`）に入る。

1. **「Management」ネットワークを消す。** SG2210P の管理インターフェースが「Management」に紐づいていて、消せない・SG2210P が切れる、場合がある（**未確認**）。そのとき:
   - SG2210P は、同じ VLAN10 の L2 なので、コントローラーから再採用できる（本体のリセットが要る。リセットの秒数は、[ER605 のときの報告](https://community.tp-link.com/en/home/forum/topic/598154)を参考に、確認する）。
   - 消せないときは、先に、SG2210P の管理 VLAN の設定を外す方法を、画面で探す。
2. **既定のネットワーク（Default）を編集する**: 名前 `Management`、VLAN `10`、IP/マスク `10.77.10.1/24`、DHCP サーバーは、**緊急用の範囲 `10.77.10.240`〜`.250`、リース 60 分、DNS `10.77.10.1`**。
3. **SG2210P の管理インターフェース**: 「デバイス → sg2210p → 設定 → インターフェース」で、`Management`（VLAN10、新しい既定のネットワーク）の管理 VLAN を有効にし、**静的 `10.77.10.2/24`、GW・DNS `10.77.10.1`**。旧 VLAN1 のインターフェース（`192.168.11.62`）は、無効にする（もう無い）。
4. p1（ER605 との接続）の native が、Management(10) の untagged になっていることを確認する（プロファイル `All` の native は Default で、VLAN10 になっているはず）。

## 4. ER605 を、VLAN10 だけで、再採用する

**Mac を、ER605 の LAN 専用ポート（p4）に挿し替える**（`192.168.0.x`）。

1. `http://192.168.0.1` → ウィザード（管理者アカウント。台帳へ）。WAN は DHCP。「Manually Connect to Omada Controller」に、Inform URL **`10.77.10.3`**。
2. **「Network → LAN」の既定の LAN を、`10.77.10.1/24`、Vlan `10` に変える**（DHCP の範囲は、緊急用の `.240`〜`.250`）。これで、ER605 の LAN が、最初から、最終形（VLAN10 の untagged）になる。SG2210P の p1（untagged VLAN10）と、そろう。Mac は、`10.77.10.x` を受け取り、コントローラー（`10.77.10.3`）に、**ルーティングなしで、同じ L2 で**届く（UFW は、`10.77.10.0/24` を許可済み）。
   - 前回（2026-11-19 の 2 回目）は、LAN を `192.168.0.1/24` のまま、別に VLAN10 を作った。今回は、LAN そのものを VLAN10 にするので、`192.168.0.0/24` の許可も、`ip route` も、要らない見込み（**未確認**）。
3. コントローラーの「デバイス」（サイトのビュー）に、ER605 が「保留中」で出る。**導入**する（アカウントを入れる）。
4. サイトの設定が配られ、各 VLAN のゲートウェイが戻る（前回は、導入から約 4 分）。

- [ ] SG2210P が「接続しました」（IP `10.77.10.2`）。
- [ ] 各 VLAN のゲートウェイ（`10.77.10〜70.1`）とインターネット、Mac（Trusted）の DHCP。
- [ ] `omada.lab.kanare.dev`、`home.lab.kanare.dev`、`grafana.lab.kanare.dev`、Prometheus の全ターゲット（`vm-dev` は、停止中）、Tailscale、Healthchecks.io。
- [ ] **untagged の試験**: p2 に、タグなしの VM を繋いだとき、どこにも出られないこと（任意。`Blackhole` の確認）。

## 戻し方

- 最悪、案 A（既定の LAN を `10.77.1.0/24` に付け替える）に切り替える。
