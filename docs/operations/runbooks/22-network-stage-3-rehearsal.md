`10.77.20.10`（`vm-infra`）は、まだ存在しない。**この段階の DHCP では、DNS が引けない**（配られる値が正しいことだけを確かめる）。

**警告（INC-2026-11-08 の教訓）**: ネットワーク（LAN）を作るウィザードの**「Select Device Port」（デバイスのポートを選ぶ）の手順で、ポートを選ぶと、そのポートが「その VLAN のアクセスポート」になる**（Native Network が、作るネットワークに書き換わり、タグ付きは Block All になる）。**その VLAN の端末を直接繋ぐポートだけ**（p5・p6 のように）選ぶ。**複数の VLAN を通すトランクポート（p1＝ER605 へ、p2＝Proxmox）は選ばない。** タグ付きは、ポートのプロファイルが `All`（Allow All）なら、作った VLAN が自動で入る。Management（VLAN10）を作るとき、**p2（トランク）を「VLAN10 をタグ付きで通すつもり」で選んだ**ため、p2 の Native が Management(10)、タグ付きが Block All になり、Proxmox のタグなしの通信が既定の LAN に届かなくなって、Proxmox と全 VM が LAN から消えた。作成のあと、SG2210P の p1〜p4 の VLAN Configuration が、Native = Default(1)、Network Tags = Allow All のままであることを確認する。

### A-4. ACL の評価順と、戻りの通信を確かめる

今は、Servers のホストが `192.168.11.x` にいるので、**今の LAN（`192.168.11.0/24`）を、Servers の代わりにして**試す。ゲートウェイの ACL（LAN → LAN）に、次のルールを、**上から順に**作る（メニューは、Settings > Network Security > ACL のあたり）。

| 順 | 動作 | 送信元 | 宛先 | 名前 | 説明 |
| --- | --- | --- | --- | --- | --- |
| 1 | 許可 | VLAN30 | 今の LAN（`192.168.11.0/24`） | `rh-010-trusted-to-lan` | `[リハーサル] Trusted → 今のLAN（Serversの代理） : 許可` |
| 2 | 許可 | VLAN30 | VLAN50 | `rh-020-trusted-to-iot` | `[リハーサル] Trusted → IoT : 許可` |
| 3 | 拒否 | VLAN50 | 今の LAN | `rh-030-iot-to-lan` | `[リハーサル] IoT → 今のLAN（Serversの代理） : 拒否` |
| 4 | 拒否 | VLAN50 | VLAN30 | `rh-040-iot-to-trusted` | `[リハーサル] IoT → Trusted : 拒否` |
| 5a | 拒否 | 今の LAN | !今の LAN | `rh-900-deny-from-lan` | `[リハーサル] 今のLAN → 他のネットワーク : 拒否（末尾）` |
| 5b | 拒否 | VLAN30 | !VLAN30 | `rh-901-deny-from-trusted` | `[リハーサル] Trusted → 他のネットワーク : 拒否（末尾）` |
| 5c | 拒否 | VLAN50 | !VLAN50 | `rh-902-deny-from-iot` | `[リハーサル] IoT → 他のネットワーク : 拒否（末尾）` |

**種類（Source Type・Destination Type）に「すべて（Any）」の選択肢はなく、宛先は、送信元に選んだネットワーク以外からしか選べない。** そのため、**末尾の拒否（5）は、ネットワークごとに 1 件**作る。送信元 = そのネットワーク、宛先 = 「!ネットワーク」でそのネットワーク（選んだネットワーク**以外のすべて**。公式の資料の例と同じ形）。「!ネットワーク」を選べなければ、宛先に、ほかのネットワークをすべて選ぶ。ルールに一致しない通信は、暗黙の許可（permit）になるので、5 が要る。インターネットは、ネットワークの一覧に入らないので、5 の対象外の見込み（**5c を作ったあと、p6 から `ping 1.1.1.1` が通ることで確かめる**）。「ネットワーク」は選んだネットワークに一致する（1〜4 で使う）。

名前と説明の付け方（検証用は `rh-` と `[リハーサル]` を付ける）は、[設計書の「ACL の名前と説明の付け方」](../../architecture/08-vlan-design.md#acl-の名前と説明の付け方)にある。本番でも同じ形にする。

**5a〜5c（末尾の拒否）は、最後に足し、足したあと、既存の通信が生きているか確認する**（`ping 192.168.11.10`、`ping 1.1.1.1`、コントローラーの画面、Wi-Fi の端末）。おかしければ、**削除でなく無効にする**。

p5（VLAN30）の Mac で:

- [x] `192.168.11.13` などに届く（ルール 1。戻りの通信が通る）
- [x] `ssh` や `curl` で、双方向のやりとり（TCP）が成立する（`ssh vm-code`（`192.168.11.22`）が成功）

p6（VLAN50）の Mac で:

- [x] `192.168.11.13` に**届かない**（ルール 3）
- [ ] ルール 4（IoT → Trusted の拒否）は、VLAN30 に**実際のホスト**が要る。2 台目の端末を p5 に繋いで、その IP（`10.77.30.1xx`）に ping して、**届かない**ことを確かめる（または、B と C-1 のあと、検証用の VM を VLAN30 に置いて確かめる）
- 注意: **`10.77.30.1`（VLAN30 のゲートウェイ自身）宛の ping は、通る。** ゲートウェイ自身宛の通信は、ゲートウェイの ACL（LAN → LAN）の対象外で、ルール 4 の確認にならない（2026-11-06 に実機で確認。誤った確認項目を直した）
- [x] `ping 1.1.1.1` は通る（インターネットは許可。**5c の「!ネットワーク」でも、インターネット宛が拒否されない**ことの確認）

結果（p6・VLAN50。2026-11-06）: `192.168.11.13` に**届かない**（ルール 3 が効いている）。`ping 1.1.1.1` は**通る**（5c の「!ネットワーク」で、インターネット宛が拒否されない）。
結果（p5・VLAN30。2026-11-06）: `ssh vm-code`（`192.168.11.22`）が成功した。**戻りの通信は通る**（TCP の双方向）。**評価は上から順**（末尾の 5b より、許可のルール 1 が先に評価された）。

## B. 恒久的な準備（`vmbr0` を VLAN-aware にする）

**時間に余裕のあるときに行う。** 稼働中の Proxmox のネットワーク設定を変える。誤ると、Proxmox に届かなくなるので、**次のどちらか（できれば両方）を用意する**。

1. **物理コンソール**（キーボードとモニター）を、すぐ繋げられる状態にする。成功すれば、使わない。
2. **自動で元に戻るタイマー**を仕掛ける（下）。接続が切れても、決めた時間に、自動で元に戻る。

今の状態（2026-11-08 に確認。変更前の基準）: Proxmox VE 9.1.7（カーネル 6.17.2-1-pve）、`ifupdown2` 3.3.0 が入っている（`ifreload` が使える）。`vmbr0` は VLAN-aware ではない（`vlan_filtering 0`）。`bridge vlan show` は、`nic0`、`vmbr0`、各 VM の `tap` が、すべて VLAN 1（PVID・untagged）。`dmesg` に `Hardware Unit Hang` は無い。`/etc/network/interfaces` は、`nic0` が `inet manual`（Ansible の ethtool の行つき）、`vmbr0` が `192.168.11.10/24`・ゲートウェイ `192.168.11.1`・`bridge-ports nic0`・`bridge-stp off`・`bridge-fd 0`。末尾に `source /etc/network/interfaces.d/*`。

### C-1. `vmbr0.10` の試験
