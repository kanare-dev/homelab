# Omada 導入・VLAN 化・OPNsense 導入

[ロードマップ](../roadmap.md)の大型計画。ER605・SG2008P・EAP（AP）で Omada のネットワークを作り、VLAN で分離し、そのあとに OPNsense を学習用に足す。設計は完了、機器は未購入で未着手。

詳細は設計書と ADR にある。この文書は、進行の順序とチェック項目だけを持つ。

## 目的

- ルーター・スイッチ・AP を Omada で一元管理する
- 管理・サーバー・クライアント・IoT・ゲストを VLAN で分け、セグメント間の通信を制限する
- OPNsense（N100）で、ファイアウォールなどネットワーク技術を学ぶ

## 基本方針

- 機器は買う順に 4 段階に分ける。段階 1〜2 の間は IP を変えない
- VLAN への切り替えは、全ホストを一斉に行う（段階 3）
- 家の入口のルーターは ER605 のままにする。OPNsense は、止まっても影響が小さい役割から試す
- 各段階で戻し方を決めてから着手する（戻し先は直前の段階の状態）

## 導入の段階

### 段階 1: ルーターの交換と Omada コントローラー

- [ ] ER605 **V2** を購入する（型番と、コントローラーのバージョンとの対応を購入前に確認する）
- [ ] Omada コントローラーを Proxmox 上の VM として立てる
- [ ] ER605 の LAN アドレスを `192.168.11.1/24` に変更してから、コントローラーで採用する
- [ ] ルーターを Buffalo から ER605 に交換し、Buffalo を AP モードにする（IP は変えない）
- [ ] 設計書・構成図を更新する

### 段階 2: Managed Switch

- [ ] SG2008P を購入する（PoE の電力予算は 62W。将来の AP の台数を確認する）
- [ ] スイッチをコントローラーで採用し、Proxmox などをつなぐ（VLAN は使わない）
- [ ] 設計書・構成図を更新する

### 段階 3: VLAN と `10.x` への一斉切り替え

- [ ] コントローラーモードの ACL で、LAN → LAN を制限できるか確認する（段階 3 の前）
- [ ] mDNS の中継（Clients ↔ IoT）が動くか確認する。動かなければ、段階 4 まで有線のテレビを Clients に置く
- [ ] TO-BE の構成図を描く
- [ ] 物理設置（ThinkCentre・ルーター・スイッチの置き場所、通気、電源、ケーブル）を決める
- [ ] 戻し手順を書く（戻し先は段階 2 の状態。Omada のバックアップと `terraform state` を事前に保存する）
- [ ] VLAN10 Management / VLAN20 Servers / VLAN30 Clients / VLAN40 IoT / VLAN50 Guests へ全ホストを一斉に切り替える
- [ ] 設計書・構成図・Terraform・Ansible・DNS の IP を更新する

### 段階 4: AP（EAP）

- [ ] AP の機種を選ぶ（Wi-Fi 6 世代の日本での入手性・価格・技適を、段階 3 の後に確認する）
- [ ] AP を設置し、SSID と VLAN を対応させる（設置場所は電波の届き方で決める）
- [ ] Buffalo を退役または予備にする

## OPNsense の導入

段階 3 のあとに、学習用のプロジェクトとして始める。

- [ ] Topton N100 などの機器を用意する（予算 2〜3 万円）
- [ ] 止まっても影響が小さい役割（セグメント間のファイアウォールなど）から試す
- [ ] TP-Link ルーターのファイアウォールとの役割分担を決め、ADR に残す
- [ ] 家の入口のルーターを OPNsense に替えるかは、運用の実績を見てから判断する

## 関連する検討

- Home Assistant の機器の検出と VLAN（Servers から Clients・IoT への mDNS の中継か、置き場所の変更）。Cast や Matter を使う前に決める
- GPU 搭載 PC の VLAN とファイアウォールルール（[GPU 搭載ゲーミング PC](gpu-pc.md) の Phase 5）
- Cloudflare Tunnel と Split-Horizon DNS は、共有のニーズが出るまで着手しない（ロードマップの方針）
