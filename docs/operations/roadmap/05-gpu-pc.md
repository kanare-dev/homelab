# GPU 搭載ゲーミング PC 兼ホームサーバー

[ロードマップ](README.md)の大型計画で、まだ着手していない。構成を決めて購入に進むときは、設計書（`docs/architecture/`）と構成図を更新し、ADR を追加する。この 3 つは、同じ変更で行う。

## 目的

PC ゲームを始めることと、ローカル LLM や機械学習を実行できる環境を作ることが目的である。GPU の計算資源をホームラボに組み込み、MacBook Pro から遠隔で操作できるようにする。将来は、ハードウェアやサーバーとしての用途を広げていく。

## 基本方針

- 予算は 20〜25 万円とし、BTO の Windows デスクトップ PC を購入する。
- 普段はヘッドレスで運用し、MacBook Pro からリモート接続する。必要なときは、ディスプレイとキーボードを直接つないで使えるようにしておく。
- GPU の性能だけでなく、拡張性、静音性、冷却性能も重視して選ぶ。
- 常時稼働させるサービスは既存の ThinkCentre に置き、GPU 搭載 PC は必要なときだけ起動する。
- 買うのは「高性能なゲーミング PC」ではなく、「ゲームもできる、拡張性の高い GPU 計算ノード」である。
- 最初の OS は、ベアメタルの Windows 11 にする。Proxmox VE は、将来の検証や移行の候補として残す。

## ハードウェア構成（候補）

| パーツ | 推奨構成 | 備考 |
| --- | --- | --- |
| CPU | Ryzen 5 7600 / Ryzen 7 7700（AM5） | 内蔵 GPU 付きが望ましい（Proxmox の GPU パススルー検証用）。Ryzen 5 7500F は内蔵 GPU なし |
| GPU | NVIDIA RTX 5060 Ti 16GB 以上 | LLM は VRAM 容量を重視。CUDA・PyTorch の互換性から NVIDIA。RTX 5070 12GB より 5060 Ti 16GB が適する場合がある |
| RAM | DDR5 32GB（将来 64GB 以上へ拡張） | 16GB × 2 のデュアルチャネルが望ましい |
| SSD | NVMe 1TB 以上 | M.2 の空きを確認。将来 Linux・VM 用に増設 |
| マザーボード | B650 / B850（拡張性重視） | メーカー・型番を確認 |
| 電源 | 750W 80 PLUS Gold 以上 | メーカー・型番、GPU 補助電源コネクタを確認。品質・静音性を重視 |
| ケース | ATX ミドルタワー（静音・冷却・拡張性重視） | 大型 GPU が入り、SSD・ファンを増設できる |
| ネットワーク | 有線 LAN（可能なら 2.5GbE） | |

購入前には、次の点を確認する。

- RAM スロットの数と、搭載できる最大容量
- M.2 スロットの数と、空きスロットの有無
- PCIe スロットの構成
- 将来、大型の GPU に交換できるか
- 電源の容量と、補助電源コネクタの数
- Wake-on-LAN に対応しているか（UEFI と NIC の両方）
- IOMMU と AMD-Vi に対応しているか（将来の GPU パススルーに使う）
- BTO メーカーの保証条件と、パーツ交換の制限

## 機種比較の優先順位

上から順に重視する。GPU・CPU の性能だけでなく、将来の拡張性とサーバー用途への転用しやすさを見る。

1. GPU VRAM 16GB 以上
2. 予算 20〜25 万円以内
3. AM5 プラットフォーム
4. RAM 32GB 以上
5. SSD 1TB 以上
6. マザーボードの拡張性
7. 電源・ケースの品質
8. Wake-on-LAN・リモート運用への適性
9. 保証・サポート・納期
10. デザイン・RGB ライティング

予算を超えそうなときは、次のように考える。

- 妥協してよいのは、CPU を Ryzen 7 から Ryzen 5 に下げること、SSD を 1TB に抑えて後から増設すること、RGB などの装飾を省くこと、高価な水冷を避けることである。
- 妥協しないのは、GPU の VRAM 16GB、AM5、マザーボードの拡張性、電源の品質、ケースの冷却性能である。
- RAM は、最初から 32GB を確保する。後から足す場合は、スロットの構成と価格を先に確認する。

## ネットワーク・運用構成

| 機器 | 役割 |
| --- | --- |
| MacBook Pro | メインの操作端末 |
| GPU 搭載 PC | ゲーム、LLM の推論、機械学習 |
| ThinkCentre | DNS、監視、Docker など、常時稼働させるサービス |
| Omada | LAN と VLAN の管理 |

運用の方針は、次のとおりである。

- GPU 搭載 PC は、有線 LAN でつなぐ。
- MacBook からは、Moonlight でゲームを遊ぶ。
- SSH で、WSL2 の Linux 開発環境に接続する。
- 起動は、Wake-on-LAN で遠隔から行う。使わないときはシャットダウンして、消費電力を抑える。
- ヘッドレスで運用するために、仮想ディスプレイを設定する。障害のときは、物理のディスプレイとキーボードをつないで復旧する。
- Open WebUI のように常時動かすフロントエンドは ThinkCentre に置き、GPU 搭載 PC 上の Ollama API に接続する。

## 設計上の注意点

- ゲームとの互換性を優先して、最初の構成には Windows 11 を採用する。
- Proxmox は最初には導入せず、将来の検証の対象にする。
- GPU を複数の VM で共有するには、技術的な制約がある。
- GPU 搭載 PC を止めている間は、LLM の API を使えない。
- Windows Update による再起動やサービスの停止を、運用で考慮しておく。
- WSL2 のサービスを自動で起動する方法と、復旧する方法は、別に設計する。
- Wake-on-LAN は、機種や設定によって動作する条件が異なる。
- 24 時間稼働させると、電気代、発熱、騒音が問題になるので注意する。

## 最終的な目標

MacBook Pro をメインの端末にして、必要なときに GPU 搭載 PC を遠隔から起動し、ゲーム、LLM の推論、機械学習を実行できる環境を作る。

既存の ThinkCentre は常時稼働のサーバーとして使い続け、GPU 搭載 PC は、必要なときに使うオンデマンドの高性能な計算ノードとして組み込む。

将来は、ホームラボの複数のサービスや Kubernetes のワークロードから、GPU を利用できる構成に発展させる。
