# Omada 導入・VLAN 化

[ロードマップ](README.md)の大型計画である。ER605、SG2210P、EAP（AP）を使って Omada のネットワークを作り、VLAN で分離する。OPNsense は、別の大型計画（[OPNsense 導入](08-network-opnsense.md)）に分け、この計画が完了したあと、機器が買いやすくなってから進める。段階 1〜3（ER605・SG2210P と VLAN）は 2026-11 に終えた。AP（EAP653）は 2026-11-28 に購入し、段階 4 はこれから行う。

詳しい内容は、設計書と ADR に書いている。この文書には、進める順序とチェック項目だけを書く。

機器を購入したあとの具体的な作業（AS-IS と TO-BE の構成図、ポートの割り当て、配線の付け替え、戻し方）は、[ER605・SG2210P の移行計画](10-er605-sg2210p-migration-plan.md)（検討中）にある。

## 目的

ルーター、スイッチ、AP を、Omada でまとめて管理する。管理、サーバー、クライアント、IoT、ゲストのネットワークを VLAN で分け、セグメント間の通信を制限する。

## 基本方針

- 機器は、買う順に 4 つの段階に分ける。段階 1〜2 の間は、IP を変えない。
- VLAN への切り替えは、全ホストを一斉に行う（段階 3）。
- 家の入口のルーターは、当面 ER605 で運用する。OPNsense への置き換えは、[別の計画](08-network-opnsense.md)で扱う。
- 各段階に着手する前に、戻し方を決めておく。戻し先は、直前の段階の状態である。

## 導入の段階

### 段階 1: ルーターの交換と Omada コントローラー

- [ ] ER605 **V2** を購入する（型番と、コントローラーのバージョンとの対応を購入前に確認する）
- [ ] Omada コントローラーを Proxmox 上の VM として立てる
- [ ] ER605 の LAN アドレスを `192.168.11.1/24` に変更してから、コントローラーで採用する
- [ ] ルーターを Buffalo から ER605 に交換し、Buffalo を AP モードにする（IP は変えない）
- [ ] 設計書・構成図を更新する

### 段階 2: Managed Switch

- [ ] SG2210P を購入する（購入前に版数を確認する。Omada コントローラーに対応しない版がある。PoE の電力予算は 61W 前後で版により異なる。将来の AP の台数を確認する）
- [ ] スイッチをコントローラーで採用し、Proxmox などをつなぐ（VLAN は使わない）
- [ ] 設計書・構成図を更新する

### 段階 3: VLAN と `10.x` への一斉切り替え

- [ ] コントローラーモードの ACL で、LAN → LAN を制限できるか実機で確認する（公式 FAQ では可能。段階 3 の前。詳細は VLAN 設計の未決事項）
- [ ] mDNS の中継（Trusted ↔ IoT）が動くか確認する。動かなければ、段階 4 まで有線のテレビを Trusted に置く
- [ ] TO-BE の構成図を描く
- [ ] 物理設置（ThinkCentre・ルーター・スイッチの置き場所、通気、電源、ケーブル）を決める
- [ ] 戻し手順を書く（戻し先は段階 2 の状態。Omada のバックアップと `terraform state` を事前に保存する）
- [ ] VLAN10 Management / VLAN20 Servers / VLAN30 Trusted / VLAN40 Lab / VLAN50 IoT / VLAN60 Guests へ全ホストを一斉に切り替える（VLAN70 DMZ は VLAN とルールだけ作る。詳細は [DMZ と外部公開](07-dmz.md)）
- [ ] 設計書・構成図・Terraform・Ansible・DNS の IP を更新する

### 段階 4: AP（EAP）

- [x] AP の機種を選ぶ。**2026-11-28 に、運用者が EAP653（Wi-Fi 6、AX3000、PoE+ 給電）を購入した**（[EAP653 の資料](../../architecture/lld/hardware/eap653.md)）。技適の表示は、本体のラベルで確かめる
- [ ] AP を設置し、SSID と VLAN を対応させる（設置場所は電波の届き方で決める）
  - SSID は 3 つで始める（検討中）: Trusted（VLAN30）/ IoT（VLAN50、2.4GHz のみ、クライアント間分離）/ Guest（VLAN60、クライアント間分離、LAN 向けは全遮断）
  - SSID の名前は、命名規約（[ADR-0042](../../adr/0042-ssid-names-by-vlan.md)、2026-11-28 に決定）に従い、`Onda`・`Onda-Forte`（Trusted）、`Onda-IoT`、`Onda-Guest` にする
  - Lab（VLAN40）の SSID は、無線で繋ぐ検証機が出てから追加する。SSID を増やすとビーコンの電波オーバーヘッドが増えるため、最小構成で始める
  - Management（VLAN10）と Servers（VLAN20）は有線のみ。SSID は出さない
- [ ] Buffalo を退役または予備にする

段階 4 で決めること（**検討中**。2026-11-28 に書き出した）:

- **AP のポートと IP は決めた（2026-11-28、[ADR-0043](../../adr/0043-ap-on-p3-native-management.md)）**: SG2210P の p3（Buffalo と差し替える）を trunk にし、ネイティブを Management（VLAN10）、タグ付きを Trusted・IoT・Guests にする。IP は `10.77.10.4`。
  - **検討中**: AP を外したケーブルに PC を挿すと Management に入れるので、物理的に触られる心配が出たら、ネイティブを `Blackhole` にし、AP の管理 VLAN をタグ付きの 10 にする（2 段階で切り替える。ADR-0043 の代替案）。
- パラメーターシート（p3、AP、SSID、WLAN）は、画面で項目と選択肢を確かめてから書く（[ADR-0044](../../adr/0044-verify-parameters-on-screen-before-writing.md)）。AP の設定（SSID、管理 VLAN、IP）は、EAP653 をコントローラーに採用するまで画面に出ない項目がある。採用の前に確かめられない項目は、手順書に「未確認」で書き、採用したあとに確かめる
- 移行の手順。`Onda` と `Onda-Forte` を、Buffalo と同じ名前・同じパスフレーズで EAP653 に出せば、端末はつなぎ直さずに移れる。p3 で差し替えるので、Buffalo を止めてから EAP653 を出す（並行して動かす時間は作らない）。EAP653 の SSID と VLAN は、コントローラーで先に作っておき、採用した直後に配られるようにする
- `Onda-IoT` に移す機器（テレビ、SwitchBot Hub 2、Tapo C200）と、移す順序。テレビを移すときに、Trusted ↔ IoT の mDNS の中継を確かめる
- Guests の SSID を、段階 4 で同時に出すか、来客の予定ができてから出すか

## 関連する検討

- Home Assistant が機器を検出する方法と、VLAN との関係を決める必要がある。Servers から Trusted と IoT へ mDNS を中継するか、Home Assistant の置き場所を変えるかのどちらかになる。Cast や Matter を使う前に決める。
- GPU 搭載 PC の VLAN とファイアウォールルールは、[GPU 搭載ゲーミング PC](05-gpu-pc.md) の Phase 5 で扱う。
- 通信の収集と可視化は、[ネットワーク通信の収集・可視化](06-network-traffic-analysis.md)で扱う。Buffalo を AP モードにして、Wi-Fi の通信をスイッチに通す構成（段階 1〜2）が、通信を取得する位置の第一候補である。そのため、ER605 の導入を先に進める。
- DMZ の VLAN は、[DMZ と外部公開](07-dmz.md)で扱う。VLAN 設計に DMZ を足すかどうかは、段階 3 の前に決める。
- Cloudflare Tunnel と Split-Horizon DNS は、共有したいというニーズが出るまで着手しない（ロードマップの方針）。

## VLAN 設計の未決事項（検討中）

基本設計（[第5章 ネットワーク](../../architecture/hld/05-network.md)）に載せる前の項目である。VLAN 設計書の未決事項のうち、終わっていないものを、ここに移した。いずれも検討中で、採用を決めたら、設計書と ADR に移す。

- [ ] **アドレス帯の重複確認**: (1) 今の上流（建物の共用ルーター）は `172.16.0.0/12` の範囲で、`10.77.0.0/16` とは被らないことを確認済み（`172.16.0.0/12` は `10.x` と重ならない）（2026-10-23、`traceroute -n 1.1.1.1` の 2 ホップ目で確認）。(2) 外出先（職場・実家など）で `10.77.x.x` が使われていないか。(3) 引っ越し先でも、最初に `traceroute` などで上流のアドレス帯を確認する。
- [ ] **DMZ の詳細**: ハニーポットと公開用 Web サーバーを同じ VLAN に置くか分けるか、DMZ の DNS の向き先（`vm-infra` か外部 DNS か）、ログ収集の方向。[DMZ と外部公開](07-dmz.md)の Phase 1 で決める。
- [ ] **DMZ の置き場所**: 決定済み（[ADR-0016](../../adr/0016-dmz-placement.md)）。まず Proxmox の同じホストで、安全な範囲（インターネットに公開しない段階）で検証する。将来は、別の小型 PC やラズパイなどを DMZ 専用にする。残る作業は、別の機器へ移す時期の判断（外部公開の前に移すか）と、同じホストの間の仮想 NIC・ブリッジの設定の確認。
- [ ] **管理画面の外部到達の見直し**: 時期は決定済み（[ADR-0016](../../adr/0016-dmz-placement.md)）。VLAN 導入後、かつ DMZ に公開するもの（ハニーポット、Web サーバー）を置く前（[DMZ と外部公開](07-dmz.md)の Phase 4 の前）に、Tailscale の ACL で整理する。
- [ ] **通信監視の受信用ホスト**: [ネットワーク通信の収集・可視化](06-network-traffic-analysis.md)のミラーポートを受ける機器。方針は、Proxmox に USB NIC を足さず（差しっぱなしと管理対象の増加を避ける）、NIC が 2 つ以上ある別の小型 PC（受信専用と管理用）を第一候補にする。OPNsense 用や DMZ 専用の機器とは兼用しない。OPNsense 導入後は、OPNsense 側で通信を取る案も別案として検討する（06 の Phase 4）。残る作業は、ミラーポートに使う SG2210P のポート、管理用 NIC を置く VLAN、機種と購入時期（Phase 2 で決める）。
- [ ] **WAN 側の繋ぎ方**: 現在は二重 NAT（建物の共用ルーター配下）。新ルーターの WAN 設定は、当面は今と同じ（DHCP で上流から受け取る）想定。引っ越し先が分かったら見直す。
- [ ] **mDNS の中継**: 段階 3 で、ER605 のゲートウェイによる Trusted ↔ IoT の中継（有線のテレビ）が動くか。動かなければ、段階 4 まで Trusted に置く。Omada コントローラーは、ゲートウェイの mDNS に v5.6 以降、Bonjour サービスの設定に v5.8 以降、AP の VLAN 間 Bonjour に v5.9 以降が必要（公式ドキュメントより。購入前に再確認する）。
- [ ] **テレビの追加通信**: AirPlay・Cast を実機で試し、IoT → Trusted に開ける必要があるポートがあるか。
- [ ] **Wi-Fi の SSID**: VLAN ごとに SSID を分けるか、1 つの SSID で端末ごとに VLAN を割り当てるか。AP の機種と Omada の機能で決まる。今の 4 つの SSID のうち、WPA2 の 2 つ（`[2.4]`、`[5]`）は**無くさない**（決定 2026-11-03）。WPA3 に対応していない端末があるかもしれず、対応を確認しきれないため。**SSID の名前は `Onda`（共通 SSID。WPA2）と `Onda-Forte`（WPA3）にする**（決定 2026-11-03。`canale` の由来のイタリア語から。Onda は波、Forte は強い）。段階 4 の VLAN ごとの SSID は、`Onda-IoT`、`Onda-Guest` にする（命名規約は [ADR-0042](../../adr/0042-ssid-names-by-vlan.md)。2026-11-28 に、小文字の案から変えた）。バンドステアリング Lite で 2.4GHz と 5GHz を共通にする（共通 SSID と WPA3 側の両方に、名前の入力欄があった）。**運用者が、2026-11-03 に、移行（段階 1）の前に設定した**（当初は、移行のあとに行う予定だった）。AP モードでも Lite が効くかは、段階 1 の手順 2 で確認する。
- [ ] **機種の選定**: ルーターは ER605、スイッチは SG2210P を想定。AP は未定（段階 3 の後に、Wi-Fi 6 の日本での入手性・価格・技適を確認して選ぶ）。Omada の対応表とコントローラーのバージョンの互換性は、購入前に公式ドキュメントで確認する。
- [ ] **コントローラーモードの ACL で LAN→LAN を制限できるか（公式 FAQ では可。実機の確認は段階 1 のあと、段階 3 の前）**: 通信ポリシー（Trusted → Management の制限、DMZ → 内部の遮断など）が成立するかに直結する。TP-Link の公式 FAQ に、ER605 V2 と Omada ソフトウェアコントローラー V5.9 で、Gateway ACL（方向は LAN→LAN、状態は Auto）により片方向の VLAN 間アクセスを作る手順が載っている（[FAQ](https://www.tp-link.com/ca/support/faq/3745/)）。以前の「コントローラーモードの ACL は LAN→WAN のみ」という記載は古い。残る作業は次の実機確認: (1) 使うファームウェアとコントローラーのバージョンで、Gateway ACL に LAN→LAN があるか。(2) 状態が Auto のとき、許可した方向の戻りの通信が通るか。(3) ルールが上から順に評価され、最初に一致したもので止まるか（公式の記載は未確認。フォーラムの報告のみ）。許可の例外は拒否より上に置く。(4) 末尾の全拒否で、許可表のデフォルト拒否を実現できるか。使えない場合は、通信ポリシーの実現方法（スイッチの ACL、ルーター側の別の機能など）を見直す。
- [ ] **物理設置**: ThinkCentre（Proxmox）、ルーター、スイッチの置き場所。棚か小型ラックか、通気、電源タップ、ケーブルの取り回し。引っ越しを考え、持ち運びしやすい形にする。AP の設置場所は電波の届き方で別に決める。ラックの導入は[大型計画](09-rack.md)で進める（10 インチラックの候補と 3D プリントのマウントは `docs/architecture/lld/hardware/rack-10inch/`）。
- [ ] **OPNsense の扱い**: ロードマップにある。TP-Link ルーターでファイアウォールを賄うか、OPNsense を別に立てるか。ルーターは ER605 V2 を先に導入し、OPNsense は段階 3 のあとに、補助的に検証してから ER605 の後継にする方針（[ADR 0009](../../adr/0009-router-er605-first.md)、計画は[OPNsense 導入](08-network-opnsense.md)）。
