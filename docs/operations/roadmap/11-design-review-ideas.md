## 構成図を 3 枚にする案

上の表の #11 の具体案。2026-11-03 に、運用者が「物理と論理が一枚で見える今の図は残しつつ、論理構成図と物理構成図もあるとよい」と述べた。**検討中で、採用していない。** 着手は、ER605 の本設置のあと。

| 図 | 見せるもの | 見せないもの |
| --- | --- | --- |
| 一枚図（今の `tobe-vlan`） | 物理と論理を重ねた全体像。そのまま残す | |
| 論理構成図 | VLAN、サブネット、ゲートウェイ（ER605）の ACL、VM とサービスの所属 | ケーブル、ポート |
| 物理構成図 | 機器、ケーブル、SG2210P のポート割り当て、PoE、リンク速度、設置場所（Buffalo と TV の近く、Proxmox の近く）。VLAN は線の色だけで示す | VM、サービス |

**物理構成図は、2026-11-06 に運用者の依頼で作った**（[`physical/`](../../diagrams/physical/make-physical.py)。段階 3 の完了後の有線。機器とポートを四角で描き、ポートごとの接続先、ケーブルの種類、VLAN を載せた）。設置場所と、リンク速度の記載は、まだ入れていない。論理構成図と、通信許可マトリクスは、検討中のまま。

作り方の案: `make-tobe-vlan.py` の部品（アイコン、枠、線、凡例）を共通のモジュールに出して、図ごとの配置スクリプトから使う。出力は `tobe-vlan` と同じ形式（単体の HTML と PNG）。

## 取り入れの目安

効果が大きく、手間が小さいもの（優先して検討する）:

1. **#4**: 管理用の Mac を DHCP 予約で固定し、Management への許可を、その IP だけにする。仕事用 PC を Trusted に置く判断との相性が良い。
2. **#3**: 通信許可マトリクス。段階 3 の ACL を実機で作るときの、元になる。
3. **#10**: ルーター・スイッチ・Proxmox の停止の Runbook。ER605 と SG2210P の導入後に、実際の戻し手順から書ける。

あとでよいもの: #6（VLAN 化のあと）、#7、#8（段階 4）、#9、#11 の物理構成図（本設置のあと）。

## 補足（レビューの内容と、私が確認した点）

- レビューは、リポジトリの文書を見ていない。そのため、実施済みのこと（#1、#5、#13）も、提案に含まれていた。
- レビューは、「ER605 の ACL だけで全通信を制御できるとは限らない」として、ゲートウェイ ACL・スイッチ ACL・ホストのファイアウォールの適用範囲の区別を求めている。08 の未決事項（コントローラーモードの ACL で LAN → LAN を制限できるか）と、同じ論点。SG2210P の ACL（230 エントリ）が、予備になる（[SG2210P の資料](../../hardware/sg2210p/spec.md)）。
