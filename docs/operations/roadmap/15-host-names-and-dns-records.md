# ホストの名前と DNS のレコード

[ロードマップ](README.md)の記録。**検討中**で、採用は決めていない。設計書と ADR には、採用を決めるまで書かない。採用したら、詳細を設計書と ADR に移し、この文書は [02](02-completed.md) に 1 行だけ残す。

## 目的

固定の IP アドレスを持つホストに、`<ホスト名>.lab.kanare.dev` の A レコードを揃えて付けたい。今は、名前を引けるホストと引けないホストが混ざっている。あわせて、ネットワーク機器（ルーター、スイッチ、AP）のホスト名の付け方を、型番の名前から役割の名前に変えるかを検討する。

名前が揃えば、`ping` や `traceroute` の結果、ログ、構成図の斜体のホスト名が、同じ名前で読める。新しいホストを足すときも、「固定 IP を持つものには、ホスト名のレコードを付ける」という一つの決まりで済む。

## 今の状態

CoreDNS のレコードは、`ansible/inventory/group_vars/infra/vars.yml` の `dns_records` で管理している。サービスの名前（`grafana`、`omada`、`pve` など）は Caddy（`10.77.20.10`）を指し、ホストの名前は、そのホストを直接指す。2026-11-27 の時点で、固定 IP のホストと、ホスト名のレコードの有無は次のとおりである。

| ホスト | IP | ホスト名のレコード | 備考 |
| --- | --- | --- | --- |
| `vm-infra` | `10.77.20.10` | あり（`vm-infra`、`infra`） | |
| `vm-monitoring` | `10.77.20.11` | あり | |
| `vm-apps` | `10.77.20.20` | あり | |
| `vm-code` | `10.77.20.30` | あり | |
| `pve01` | `10.77.10.10` | あり | [IP アドレス一覧](../../architecture/lld/network/ip-addresses.md)の DNS の表には載っていない |
| `vm-omada` | `10.77.10.3` | なし | 管理画面は `omada`（Caddy 経由）で開く |
| `vm-dev` | `10.77.40.10` | なし | |
| ER605 | `10.77.10.1` | なし | Omada のデバイス名は `er605` |
| SG2210P | `10.77.10.2` | なし | Omada のデバイス名は `sg2210p` |
| Buffalo WSR-1800AX4P | `10.77.30.50` | なし | AP モード |

## 案 1: 固定 IP のホストすべてに A レコードを付ける

上の表で「なし」のホストに、`dns_records` で A レコードを足す。ネットワーク機器の名前は、案 2 で決めたものを使う。機器そのものの管理画面は使わない（ER605 と SG2210P は Omada が管理している）ので、足すのは A レコードだけで、Caddy の転送は足さない。`pve01` は、レコードはあるので、IP アドレス一覧の表に足すだけにする。

この案には、注意する点が一つある。名前を引くのは `vm-infra`（AdGuard Home と CoreDNS）である。ネットワーク機器に入りたくなるのは、たいてい障害のときで、そのときは `vm-infra` も止まっているかもしれない。また、Management の緊急用 DHCP プールは、ルーター（`10.77.10.1`）を DNS として配る。ルーターは `*.lab.kanare.dev` を引けないので、緊急時には、もともと名前が使えない（[ADR-0027](../../adr/0027-servers-octet-bands-and-emergency-dns.md)）。このため、名前は普段の操作を読みやすくするためのものと割り切る。監視の対象（Prometheus、blackbox-exporter）と、緊急時の手順書は、今までどおり IP で書く。

## 案 2: ネットワーク機器のホスト名の付け方

ネットワーク機器のホスト名を、どう付けるかの案である。どちらの案でも、Omada のデバイス名と、DNS の名前と、構成図のホスト名を揃える。

| 案 | 名前の例 | 長所 | 短所 |
| --- | --- | --- | --- |
| 2-A | `er605`、`sg2210p`（今のまま。型番の小文字） | 名前を見れば機種が分かる。今の Omada の設定を変えずに済む。 | 機器を別の機種に替えると、名前と中身が合わなくなる。同じ機種を 2 台にすると、番号を付け足すことになる。 |
| 2-B | `rtr01`、`sw01`、`ap01`（役割と番号） | 機器を替えても名前が残る。Proxmox ホストの `pve01`（[手順書 26](../runbooks/26-rename-pve-host-to-pve01.md)。増えても重ならないように番号を付けた）と、付け方が揃う。 | 機種は、名前からは分からない（設計書と構成図で分かる）。Omada のデバイス名と、文書の書き方を変える手間がかかる。 |

`router01`・`switch01` のような長い形も考えられる。ただ、`pve01` の短さと揃えるなら、`rtr01`・`sw01`・`ap01` の方が合う。

現時点の推奨は、**2-B（役割と番号）**である。ルーターは、[OPNsense への置き換え](08-network-opnsense.md)を計画しているので、型番の名前は、いずれ意味が合わなくなる。to-be の構成図の `AP1` も、`ap01` として同じ付け方に入れられる。

## 決めること

- 案 1 を採るか。採るなら、ホスト名のレコードを持つかどうかを、設計書（[DNS](../../architecture/lld/network/dns.md)）の決まりとして書く。
- 案 2 で、2-A と 2-B のどちらにするか。2-B なら、短い形（`rtr01`）と長い形（`router01`）のどちらにするか。
- Buffalo の名前。今は AP として Trusted（VLAN30）にいる。2-B なら `ap01` になるが、AP を足したとき（[04](04-network-omada-vlan.md)）に Buffalo を外すなら、名前を新しい AP に譲るのか、番号を進めるのかを決める。
- `vm-omada`・`vm-dev` のように、`vm-` で始まる今の VM の名前は、この検討では変えない。

## 採用を決めるときの手順

- DNS と、Omada の GUI でしか変えられない設定（デバイス名）は、壊れたときの影響が大きいか、コードで管理していない。このため、リポジトリの決まりでは「文書が先」になる。変えたあとの値を PR で書き、マージしてから実機を変える。
- 直す文書: [IP アドレス一覧](../../architecture/lld/network/ip-addresses.md)の DNS の表、[DNS](../../architecture/lld/network/dns.md)、[Omada コントローラーと管理対象機器](../../architecture/lld/network/omada-controller.md)のデバイス名、`README.md` のホストの表、構成図（as-is と to-be。ネットワーク機器に斜体のホスト名を足す）。
- 直すコード: `ansible/inventory/group_vars/infra/vars.yml` の `dns_records`。
- 名前の付け方（案 2）を決めたら、ADR に残す。
