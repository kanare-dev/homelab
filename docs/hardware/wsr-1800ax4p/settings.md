# WSR-1800AX4P（Buffalo Wi-Fi ルーター）

Buffalo WSR-1800AX4P の設定の詳細設計。Buffalo は画面でしか設定できず、設定を Git で管理できないので、**この文書を設定値の正とする**。製品の仕様は[ハードウェアの資料](spec.md)、交換と AP モード化の手順は[ER605・SG2210P の移行計画](../../operations/roadmap/10-er605-sg2210p-migration-plan.md)にある。

> [!NOTE]
> 取得日は 2026-11-03。ファームウェアは Ver.1.11（R32.52/B1.07）。画面の内容を書き写した。**秘密の値（Wi-Fi の暗号化キー、WPS の PIN、管理パスワード）と、機器の MAC アドレスは書かない**（リポジトリは公開）。それらはパスワードマネージャーと台帳（`private/secrets-inventory.md`）で管理する。

## 位置づけ

| 時期 | 役割 | 動作モード |
| --- | --- | --- |
| 現在 | 家のルーター（NAT、DHCP、Wi-Fi）。建物の共用ルーターの下に置く（二重 NAT） | ルーター |
| 段階 1 の後（ER605 に交換） | Wi-Fi の入口（SSID は今のまま）。有線のハブとしても働く | AP（ブリッジ） |
| 段階 4 の後（Omada の AP を導入） | 退役、または予備 | — |

AP モードにしたあとは、「[AP モードでの扱い](#ap-モードでの扱い)」の項目だけを管理する。ルーターモード専用の項目は、段階 1 で ER605 に移った時点で役目を終える。

## 運用

- Buffalo の設定を変えたら、**同じ変更でこの文書を更新**し、[変更履歴](#変更履歴)に 1 行足す。
- 設定を変えるたびに、本体のバックアップを取る。画面の「管理」→「設定管理/再起動」→「設定ファイルを保存する」で保存し、**「パスワードを使用する」を有効にして暗号化**する（ファイルには Wi-Fi のキーと管理パスワードが入る）。
- バックアップは iCloud Drive の `homelab/` に置き、ファイル名は `wsr-1800ax4p-bk-YYYYMMDD.bin`（例: `wsr-1800ax4p-bk-20261103.bin`。拡張子は、Buffalo が保存するファイルのまま）。直近の 3 世代ほどを残す。暗号化のパスワードはキーチェーンに入れる。
- 設定ファイルは、Git には入れない。

## 設定値（現在、ルーターモード）

### Internet

| 項目 | 値 |
| --- | --- |
| IP アドレスの取得 | DHCP サーバーから自動取得（上流は建物の共用ルーター。`172.22.0.0/21` の範囲） |
| 拡張設定 | デフォルトゲートウェイ、DNS: 未設定（自動取得）。MAC アドレス: デフォルトを使用。MTU: 1500 バイト |
| PPPoE | 接続先なし |
| Dynamic DNS | 使用しない |
| アドレス変換（NAT） | 使用する。TCP タイムアウト 2500 秒 |
| IPv6 | 接続方法は「インターネット＠スタートを行う」。接続状態は無効（グローバルアドレスなし）。DHCPv6-PD で自動取得、ステートレスで配布 |

### LAN と DHCP

| 項目 | 値 |
| --- | --- |
| LAN 側 IP アドレス | `192.168.11.1` / `255.255.255.0` |
| DHCP サーバー | 使用する。割り当て範囲は `192.168.11.60` から 40 台（`.60`〜`.99`）。除外アドレスなし |
| リース期間 | 48 時間 |
| 配るデフォルトゲートウェイ | エアステーションの LAN 側 IP（`192.168.11.1`） |
| 配る DNS | 指定した IP: プライマリー `192.168.11.11`（AdGuard）、セカンダリー `1.1.1.1` |
| 配る WINS / ドメイン名 | 通知しない / 取得済みのドメイン名（なし） |
| 手動割当（固定リース） | 1 件（`192.168.11.60`）。MAC アドレスは台帳 |
| 自動割当 | 7 件（取得時点） |
| 経路情報 | なし |

画面の項目名は、DHCP の「拡張設定」の並び順から判断した。

## AP モードでの扱い

背面の AUTO/MANUAL スイッチを MANUAL にして、ROUTER/AP/WB スイッチを AP にする（[Buffalo の資料](spec.md)）。Buffalo の FAQ で使えなくなると明記されているのは、DHCP サーバー、アドレス変換、パケットフィルター、PPPoE マルチセッション、IP Unnumbered。

| 項目 | ルーターモード | AP モード |
| --- | --- | --- |
| Internet、PPPoE、DDNS、アドレス変換、IPv6 の接続 | 使う | 使えない（上流は ER605 が担う） |
| DHCP サーバー、リース、経路情報 | 使う | 使えない（ER605 が担う） |
| ファイアウォール、IP フィルター、パススルー、ポート変換、DMZ、UPnP、QoS | 使う | 使えない見込み。切り替え後に実機で確認する |
| 無線（SSID、暗号化、チャンネル、隔離、MAC 制限） | 使う | **使う（この文書で管理する）** |
| EasyMesh、WPS、AOSS、マルチキャスト制御 | 使う | **使う見込み** |
| ゲストポート | 使えるが未使用 | 製品ページに「一部機能はルーター動作時のみ」の注記あり。使わない |
| システム設定（管理パスワード、NTP）、ログ、ファームウェア更新 | 使う | **使う** |
| AP 自身の LAN 側 IP アドレス | `192.168.11.1`（ルーター） | 固定（**決定 2026-11-03**: 段階 1 で `192.168.11.2`、段階 3 の VLAN 化のあとは Trusted の `10.77.30.50`。[VLAN 設計](../../architecture/08-vlan-design.md#固定アドレス)）。設定画面の入り方は、取扱説明書かエアステーション設定ツールで確認する |

| 項目 | 現状 | 提案 | AP モードで関係するか |
| --- | --- | --- | --- |
| EasyMesh | **無効にした（2026-11-03）**。変更前は有効（接続 0 台）で、画面に「SSID1 と SSID2 の設定は反映されません」の注記 | 無効にしたあと、Wi-Fi の設定が今のまま効くか確認する（**確認済み、2026-11-03**） | 関係する |
| WPS（外部 Registrar を含む） | 有効 | 使っていなければ無効にする | 関係する |
| ネット脅威ブロッカー 2 | 使用するが、ステータスが「確認中」、有効期限が空 | 使っていないなら、使わないと記録する。時刻（NTP）が取れているか確認する | 関係する（AP モードでも使える機能とされる） |
| 無線 LAN からの設定の禁止 | 禁止しない | AP 化後は Trusted の Wi-Fi から管理画面に入れる。有線だけにするか決める | 関係する |
| UPnP、PPTP パススルー | 有効 | 無効にする | 関係しない（ER605 に替われば消える） |
| IPv6 の接続方法 | 「インターネット＠スタートを行う」 | IPv6 を使わない方針（[ADR-0017](../../adr/0017-ipv6-disabled.md)）に合わせて「使用しない」にする。接続状態は無効で、実害はない | 関係しない |
| DHCP が配る DNS | `192.168.11.11` と `1.1.1.1` の 2 つ | **決定（2026-11-03、[ADR-0024](../../adr/0024-dhcp-dns-single-no-fallback.md)）: ER605 の DHCP は `vm-infra` だけにして、`1.1.1.1` は外す**（[VLAN 設計](../../architecture/08-vlan-design.md)の方針どおり）。併記すると、広告ブロックと `lab.kanare.dev` の名前解決が、たまに外れるため。止まったときの扱いは、[障害時切り分け](../../operations/runbooks/11-troubleshooting.md#vm-infra-の停止で名前解決が止まったとき仕事用-pc)。Buffalo のこの設定は、ER605 への交換まで、そのまま | 関係しない（ER605 の DHCP の設計に反映済み） |

見直しを実施したら、この表の「現状」と「設定値」を更新し、変更履歴に記録する。
